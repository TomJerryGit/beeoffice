# 远端 main 整合方案（2026-10-27）

## 1. 现状

| 项 | 值 |
|---|---|
| 本地发布分支 | `wps-run-ui-2026-10-22`（当前基于 `main`，阶段 4 / v5.0.28） |
| 远端 `origin/main` | 另一条较新的 v5.3.1 历史（`7ba409c` 附近） |
| 分叉 | `origin/main` 独有 **58** 个提交；本地独有 **209** 个提交 |
| 共同祖先 | 较旧版本，之后两边各自演进 |
| 当前策略 | 本地改动只推 `wps-run-ui-2026-10-22`，**从未 force-push main** |

结论：这不是普通“落后几个提交”，而是两条独立产品线；直接 `git merge` 会产生大量冲突，
且会把 209 个本地提交的历史与 58 个远端提交混在一起，风险高。

## 2. 可选方案对比

| 方案 | 做法 | 风险 | 建议 |
|---|---|---|---|
| A. 无关联历史合并 | `git merge origin/main --allow-unrelated-histories` | 极高：冲突多、测试基线失效、历史难回溯 | ❌ 不采用 |
| B. 本地 rebase 到 origin/main | `git rebase origin/main` 209 个提交 | 极高：每提交冲突，发布 tag 失效 | ❌ 不采用 |
| C. **从 origin/main 拉集成分支，按功能搬运本地改动** | `git switch -c integration/main-ui-2026-10-27 origin/main`，分批 cherry-pick/重放 UI、主题、发布工具 | 中：需要逐文件适配，但可测试、可回滚 | ✅ **推荐** |
| D. 以 origin/main 为准，本地归档 | 本地分支仅作为补丁来源，逐批 port | 中：本地功能需重做 | ⚠️ 备选 |

## 3. 推荐方案 C（集成分支 + 功能分批）

### 阶段 0：冻结与备份
```powershell
git branch backup/local-5028-2026-10-27 HEAD
git bundle create D:\beeoffice_backup_2026-10-27.bundle --all
```
- 保留 v5.0.x 发布 tag；集成期间本地 `main` 不动，只在新分支操作。

### 阶段 1：差异审计（只读）
```powershell
git fetch origin
git diff --stat origin/main...HEAD > _ptmp/analysis/main_divergence_stat.txt
git diff --name-only origin/main...HEAD > _ptmp/analysis/main_divergence_files.txt
```
输出三张清单：
1. 两边都改过的文件（冲突热点）；
2. 只有本地改的文件（可安全搬运）；
3. 只有远端改的文件（不能覆盖）。

重点检查：`beeoffice/app.py`、`beeoffice/plugins/*`、`tests/`、`pyproject/requirements`、
`tools/check_gates.py`、`.github/workflows/`。

### 阶段 2：建立集成分支
```powershell
git switch -c integration/main-ui-2026-10-27 origin/main
```
不直接合并；从 `origin/main` 的架构出发。

### 阶段 3：按功能批次搬运（每批独立 commit + 测试）
建议顺序（从依赖少到多）：
1. **发布工具链**：`tools/verify_release.py`、`tools/sync_version.py`、`.github/workflows/`；
2. **主题系统**：`theme.py`、`ribbon_icons.py`、`ribbon_widget.py`；
3. **Ribbon 外壳**：BeeWrite / BeeSheet / BeeShow 的 `_ribbon` 接入；
4. **测试与文档**：`tests/fidelity/test_*ribbon*`、`test_theme_*`、`test_phase4_*`、`CHANGELOG`；
5. **版本号**：按远端发布号重新定版（例如 v5.3.2），不沿用 v5.0.x。

每批：
```powershell
git cherry-pick <local-commit>      # 或按文件重放
python tools/check_gates.py
python -m pytest tests/fidelity tests/unit -q
git commit --amend --no-edit        # 必要时调整
```

### 阶段 4：PR 与验收
- 推送 `integration/main-ui-2026-10-27`，开 PR 到 `origin/main`；
- PR 描述列出功能批次、截图、门禁/全量结果；
- 由人工审查后合并，**不 force-push、不改写远端历史**；
- 合并后本地 `main` 重新从 `origin/main` 拉取，保留 `wps-run-ui-2026-10-22` 作为历史归档。

## 4. 验收标准

- [ ] 集成分支上 46/46 门禁 PASS；
- [ ] 全量 `fidelity+unit` 0 failed；
- [ ] 三插件 Ribbon/主题/上下文截图通过；
- [ ] 发布包 `verify_release.py` 5/5；
- [ ] 远端 main 历史不变（无 force-push）；
- [ ] CHANGELOG 明确记录“从 v5.0.x 分支搬运”的批次。

## 5. 不做什么

- 不在 `main` 上直接 merge 本地 209 个提交；
- 不删除本地发布 tag；
- 不把 v5.0.28 安装包直接当作远端 v5.3.x 的升级包（版本线与配置可能不兼容）；
- 不在 CI 未稳定前自动合并。
