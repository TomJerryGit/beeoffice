# 全量测试稳定性报告

日期：2026-11-19  
版本：v5.8.28

## 现象

一次性运行：

```text
pytest tests
```

在约 7% 进度处出现：

```text
Windows fatal exception: code 0x80000003
```

崩溃位置不固定：

- 一次在 `tests/qt/test_app.py::test_new_beeshow` 的 `_show_slide`；
- 两次在 `tests/qt/test_beesheet_import.py` 附近。

不是断言失败，是 Qt/WebEngine 进程级崩溃。

## 分段验证结果

| 分组 | 结果 |
|---|---:|
| tests/qt | 616 passed |
| tests/unit | 789 passed |
| tests/regression | 129 passed |
| 根目录其余测试 | 155 passed |
| 合计 | **1689 passed** |

分段运行全部通过，说明业务逻辑无回归。

## 判断

- 单测/回归/根测试稳定；
- Qt 套件单独运行稳定；
- 一次性混合运行时 WebEngine 进程偶发崩溃；
- 属于测试基础设施问题，不是功能失败。

## 临时方案

新增：

```text
tools/run_tests_chunked.py
```

CI 使用分段执行：

```powershell
python tools/run_tests_chunked.py
```

优点：

- 规避单进程累计 WebEngine 状态；
- 任一子套件失败仍返回非 0；
- 保留完整测试覆盖。

## 后续修复方向

1. 定位 WebEngine 初始化/销毁顺序；
2. 在 pytest 会话间强制隔离 Qt 进程；
3. 对含 WebEngine 的测试加单独 worker；
4. 评估 `QTWEBENGINE_CHROMIUM_FLAGS` 与 GPU/沙箱组合；
5. 建立崩溃日志采集（minidump 或 WebEngine 日志）。

## 当前结论

```text
业务测试：1689 通过（分段）
一次性全量：仍有 WebEngine 偶发崩溃，不能宣称稳定通过
```
