# BeeOffice 架构 RFC（草案）

状态：Draft  
日期：2026-11-18  
目标：用 6 个月逐步收敛文档模型与依赖边界，禁止大爆炸重写。

## 1. 分层

```text
ui/        Qt 控件、Ribbon、对话框
app/       用例、命令、撤销、事务
domain/    文档模型、规则、对象模型
adapters/  DOCX/XLSX/PPTX/PDF、WPS/MS 验收
infra/     存储、日志、配置、AI、网络
```

## 2. 依赖规则

- domain 不依赖 Qt；
- ui 不直接读写文件；
- adapter 不互相调用；
- 禁止跨 Mixin 访问私有属性；
- 新功能只允许写 domain/app；
- 元数据 schema 版本化，解析必须容错。

## 3. 文档模型 v1

- 三模块统一 `Document` 根对象；
- 节点：段落/表格/图片/形状/图表/占位符/批注/域；
- 每个节点有稳定 id、样式、位置、来源；
- 导入导出只通过 adapter；
- 撤销/重做基于命令与快照混合。

## 4. 迁移策略（绞杀者模式）

1. 新功能写新服务；
2. 旧 Mixin 只做转发；
3. 每两周迁移一个模块；
4. 迁移前必须有契约测试；
5. 迁移后删除旧路径，禁止双写。

## 5. 元数据 schema

```text
beeoffice-shapes/v1
beeoffice-chartobj/v1
beeoffice-master/v1
beeoffice-table-style/v1
beeoffice-anim/v1
```

要求：

- 带版本号；
- 未知字段保留；
- 解析失败不崩溃；
- 外部编辑后仍可恢复。

## 6. 测试策略

- domain 单测 70%
- adapter 契约测试 20%
- UI 冒烟 10%
- 真实语料/WPS/MS 验收必跑

## 7. 决策记录

- ADR-001：冻结功能，先修地基

- ADR-003：真实语料优先于 mock
- ADR-004：发布必须签名与干净机验收
