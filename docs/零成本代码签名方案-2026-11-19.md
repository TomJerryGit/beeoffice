# 零成本代码签名方案

日期：2026-11-19  
背景：没有预算采购商业 OV/EV 证书。

## 方案优先级

### 方案 A：SignPath Foundation（推荐）

面向开源项目的免费代码签名：

- 由 SignPath Foundation 签发证书；
- 适用于 OSI 认可许可证的公开项目；
- 需要公开仓库、可复现构建、签名策略、发布记录；
- 属于**酌情审核**，不保证通过。

官方：

- https://signpath.org/
- https://signpath.org/terms.html

申请前准备：

- [x] MIT License
- [x] 公开 GitHub 仓库
- [x] `CODE_SIGNING_POLICY.md`
- [x] 发布物 SHA256
- [ ] GitHub Actions 构建
- [ ] 至少一个正式 Release
- [ ] 维护者启用 MFA
- [ ] 项目无恶意行为

### 方案 B：Certum 开源证书

部分渠道提供开源免费证书，但通常要求：

- 公开 GitHub 项目
- 较高 Star 数
- 至少一个 Release

当前 BeeOffice 可能不满足 Star/影响力门槛，作为备选。

参考：

- http://certumcodesign.cn/shop/product/open-source-code-signing-cloud/

### 方案 C：自签名证书 + 企业分发（零成本，但非公共信任）

适用：

- 内部/企业环境
- 已知用户群
- 可手动安装根证书

不适用：

- 公开下载
- 消除 SmartScreen
- 企业采购默认信任

### 方案 D：继续 Unsigned Beta

适用：

- 早期测试
- 开发者/技术用户

必须披露：

```text
Unsigned
SmartScreen may warn
No clean-machine validation
```

并提供 SHA256 与 VirusTotal 链接。

## 申请材料模板（SignPath）

```text
Project name: BeeOffice
Repository: https://github.com/TomJerryGit/beeoffice
License: MIT
Build system: GitHub Actions / local PyInstaller
Signing policy: CODE_SIGNING_POLICY.md
Release artifacts:
  - BeeOffice-vX.Y.Z-windows.zip
  - BeeOffice-Setup-vX.Y.Z.exe
Build command: python build.py && python tools/build_installer.py --skip-build
```

## 实施步骤

1. 推送最新代码与至少一个 Release 到 GitHub；
2. 添加 GitHub Actions 构建工作流；
3. 提交 SignPath Foundation 申请；
4. 审核通过后，在 CI 中调用 SignPath 签名；
5. 对 exe/安装器做 `signtool verify /pa`；
6. 把签名结果与 SHA256 写入发布说明。

## 结论

> 没有预算时，唯一有希望获得“公共信任”的路径是 SignPath Foundation / 开源证书；
> 自签名只能解决内部信任，不能解决 SmartScreen。
