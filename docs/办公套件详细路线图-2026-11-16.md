# BeeOffice 办公套件详细路线图（16 周 P0）

日期：2026-11-16  
基线：v5.4.7 Beta  
总纲：[办公套件总体路线图](办公套件总体路线图-2026-11-16.md)

## 0. 执行假设

```text
1 名开发者 + AI 助手
每周 5 个工作日
约 20% 时间用于测试、回归、发布
P0 总周期：16 周
```

原则：

1. 每个 Wave 只主攻一个模块，其他模块只做 bugfix；
2. 每周必须有可验收产物，不把测试堆到最后；
3. 每个功能必须有“失败复现→实现→回归”测试；
4. 每个 Wave 结束发一个 Beta，不直接冲 Stable；
5. Stable 仍被签名证书/干净机验收阻塞。

## 1. 依赖关系

```text
共享打印/导出框架
   ├─ Excel 页面/打印
   ├─ Word 页眉页脚/页码
   └─ PDF 页面缩略图/打印

共享撤销/重做
   ├─ Excel 数据/格式
   ├─ Word 样式/分页
   ├─ PDF 页面操作
   └─ PPT 画布编辑

往返测试
   ├─ DOCX
   ├─ XLSX
   ├─ PDF
   └─ PPTX
```

**先做共享打印/导出框架（Wave 1 前半周），再进各模块。**

## 6. 每周固定工作

无论哪个 Wave，每周固定：

```text
周一：功能实现
周二：功能实现
周三：测试 + 回归
周四：修复 + 文档
周五：全量测试 + 安全扫描 + 构建冒烟 + 更新 CHANGELOG
```

发布前额外：

```text
python tools/security_scan.py
python tools/release_check.py --skip-coverage
python -m pytest tests
```

## 7. Wave 5：P1 详细入口

P0 完成后再排，建议顺序：

1. Word：封面/形状/页面装饰/比较/加密
2. Excel：图表/透视表/条件格式管理器/AI 表格
3. PDF：插入/页面加工/对比/证书签名/OCR/Office 转换
4. PPT：形状/图表/母版/视图/审阅/AI 生成

P1 每个模块预估 2–3 周，合计 8–10 周。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 16 周估算偏乐观 | 每 Wave 结束复盘，宁可延后不砍测试 |
| PPT 画布改动大 | 单独 Wave，先对象模型 |
| Word 分页复杂 | 先 20 页基线，不追 100 页 |
| Excel 大文件卡顿 | 虚拟网格 + 性能测试 |
| PDF 文字编辑受限 | 明确不做任意排版编辑 |
| 无签名/干净机 | 继续 Beta，不发布 Stable |

## 11. 结论

这份详细路线图的核心是：

```text
每 4 周交付一个模块的 P0 Beta；
每个 Beta 都必须能打印/保存/往返/撤销；
不追求四个模块同时“像 WPS”，而是逐模块形成完整工作流。
```
