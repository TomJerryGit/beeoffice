# BeeOffice v5.4.5 软件分析、审计与评价

日期：2026-11-12  
对象：`D:\beeofficeV\_ptmp\s4`，版本 `5.4.5`  
发布：https://github.com/TomJerryGit/beeoffice/releases/tag/v5.4.5

## 1. 软件定位

BeeOffice（蜜蜂办公）是 Windows 桌面办公套件，Python 3.11 + PySide6 6.x 实现，主打本地优先、轻量安装、Markdown/富文本/表格/演示/PDF 一体化：

| 模块 | 能力 |
|---|---|
| BeeWrite | Markdown/富文本编辑、表格、图片、批注、书签、导出 DOCX/PDF/HTML |
| BeeSheet | 表格、公式、筛选/排序、条件格式、图表、透视表、导入导出 |
| BeeShow | 演示文稿、PPTX/HTML、视频、同步演示、AI 大纲 |
| PDF 工具箱 | 合并/拆分/批注/书签等 |
| 云同步 | WebDAV/Google Drive/OneDrive 适配层 |
| 扩展 | 插件系统、命令面板、宏录制、AI 辅助 |

## 2. 规模与结构

```text
源码：152 个 Python 文件，54,465 行
测试：180 个文件，20,219 行
最大模块：
  beesheet_engine.py        1,878 行
  app.py                    1,572 行
  beeshow_pptx_engine.py    1,501 行
  beewrite_rich_editor.py   1,398 行
  beesheet_data_mixin.py    1,391 行
```

优点：

- 功能按领域拆成 Mixin/插件，插件化方向正确；
- 测试量较大，覆盖了核心逻辑、GUI 冒烟、回归和 P0 安全用例；
- 文档、CHANGELOG、验收记录、第三方许可说明较完整。

风险：

- 单文件过大（多个 1,000–1,900 行模块），Mixin 耦合深，修改容易跨文件回归；
- 源码中 `except Exception` 约 **622 处**，大量异常被吞掉，排障和错误可观测性不足；
- 没有统一的类型检查/静态检查配置（未见 mypy/ruff/flake8 配置）。

## 3. 质量与测试

```text
全量测试：1550 passed
全仓语句覆盖率：约 66.5%
核心模块覆盖率：12/12 = 100%
测试文件：180
```

评价：

- 核心算法/数据/协议层达到 100% 语句覆盖，是明显优点；
- 但 66.5% 是**语句覆盖率**，不是分支覆盖率；GUI 仍有大量未执行路径；
- 后期测试中有不少“为了覆盖率”构造的 mock/冒烟用例，能证明代码被执行，不能完全证明真实用户路径；
- v5.4.4 发布后才发现 `_split_cell` 的 `colSpan()` 崩溃，说明 GUI 表格路径的发布前回归不足；
- 建议补分支覆盖率、真实 Qt 事件循环测试、发布前必跑的 GUI 回归清单。

## 4. 安全审计

### 4.1 高危模式扫描

工具：`tools/security_scan.py`（AST，不是正则）

```text
shell=True          0
pickle.load/loads   0
内置 exec()         0
内置 eval()         2 条，均为 AST 白名单 guarded
Qt .exec()          不扫描（模态对话框，不是代码执行）
```

### 4.2 已修复问题

- **旧 `formula_engine._eval_math` 裸 eval**：可访问属性/下标，存在沙箱逃逸前置条件；已改 AST 白名单。虽然生产路径未引用该旧引擎，但不应留在发布包中。
- **`build_release.py` exec**：改为正则读取版本号，移除构建期代码执行。
- **`RichTextEditor._split_cell`**：`colSpan()` 不存在，改为 `columnSpan()`。

### 4.3 仍存在的安全风险

1. **安装包未签名**：SmartScreen 会拦截，用户无法验证发布者；企业环境可能直接阻止。
2. **没有独立安全审计/渗透测试**：当前只是代码级扫描和少量回归。
3. **依赖版本只写 `>=`**：没有 lockfile/SBOM，构建不可完全复现；供应链风险偏高。
4. **动态插件导入**：插件管理器会 import 本地 `*_plugin.py`，插件代码属于本地信任边界；插件市场安装的代码需要额外审查。
5. **网络/云同步**：凭据处理有 DPAPI/回退方案，但外部 API、WebDAV、更新检查未做独立威胁建模。
6. **622 处宽泛异常**：可能掩盖失败，间接影响安全事件可观测性。

### 4.4 许可证

- 项目自身：**MIT**；
- `THIRD_PARTY_NOTICES.md` 提到 PyMuPDF 是 **AGPL-3.0**，分发二进制有强 copyleft 义务；
- 当前 `requirements.txt` 将 PyMuPDF 放在开发依赖，且发布包 `dist/BeeOffice` 未检索到 `fitz/pymupdf`，所以**当前二进制未打包该 AGPL 组件**；
- 但文档表述容易让用户误以为发布包包含 AGPL 依赖，建议在发布说明中明确“PyMuPDF 仅测试使用，未进入安装包”，并保持打包检查。

整体安全评分：**7.5/10**（本地工具定位尚可，公开发布信任链不足）。

## 5. 发布与运维

已有：

- `test.yml`：快速回归 + 全量测试；但 **full 任务 `continue-on-error: true`，不阻塞合并**；
- `release-windows.yml`：手动 Windows 构建 + 可选签名 + artifact；
- `windows-install-smoke.yml`：GitHub Windows Server 上下载 Release、校验 SHA-256、静默安装、offscreen 启动、静默卸载；最近一次运行成功。

不足：

- 全量测试/覆盖率/安全扫描没有作为合并/发版的硬门槛；
- GitHub runner 是 **Windows Server**，不是 Win10/11 客户端；安装冒烟通过不等于干净机验收；
- 未签署安装包，未做 Win11 验证；
- 发布 v5.4.4 后当天又发 v5.4.5 修 UI 崩溃，说明发版前的 GUI 回归门禁不够。

## 6. 产品与体验评价

优点：

- 模块覆盖面广，本地优先，适合个人/小团队轻办公；
- 表格公式、文档导出、演示、PDF 工具集成度高；
- 安装到用户目录、无需管理员权限，降低部署门槛；
- 文档和风险披露较坦诚。

不足：

- 安装包 ~152 MB、ZIP ~221 MB，体积偏大；
- 未签名，首次安装信任成本高；
- 无 Win11/干净机数据，企业采购难以直接采用；
- 大型 GUI 代码库的可维护性和长期演进风险较高；
- AI/云同步/插件市场属于外部依赖面，离线场景之外的行为需要更多验证。

## 8. 建议

### P0（发布前必须）

1. 配置代码签名证书；
2. 在真实 Win10 干净机或云 VM 完成安装/启动/卸载验收；
3. 将全量测试、安全扫描、安装冒烟设为发版硬门槛；
4. 发布说明继续明确“未签名、无干净机验收、Win11 未验证”。

### P1（近期）

1. 增加依赖锁文件/SBOM，固定构建环境；
2. 补分支覆盖率，重点覆盖表格/富文本/导出 GUI；
3. 引入 ruff/mypy/pyright 与依赖漏洞扫描；
4. 清理宽泛 `except Exception`，至少记录上下文；
5. 对插件市场安装增加来源/签名校验。

### P2（中期）

1. 拆分超大模块（`app.py`、`beesheet_engine.py`、`beewrite_rich_editor.py`）；
2. 建立 Win10/11 兼容矩阵；
3. 加入崩溃上报隐私策略和性能基准（启动、打开大文件、导出）；
4. 提供 SBOM 和第三方许可证自动检查。

## 9. 审计结论

BeeOffice 是一个功能完整、测试投入较大、安全基线已明显改善的本地办公软件。  
作为个人/内部工具，当前 v5.4.5 具备可用性；作为面向公众或企业的正式发行版，**签名、干净机验收、依赖可复现和 CI 硬门槛**仍是明显缺口。

**结论：可用，但尚未达到“可审计、可信任公开发行”的成熟度。**
