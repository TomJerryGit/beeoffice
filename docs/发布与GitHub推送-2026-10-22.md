## 5. 推送脚本（2026-10-22 补充）

已提供可复用的重试脚本（ASCII、PowerShell 5.1 兼容）：

| 仓库 | 脚本 |
|---|---|
| BeeOffice | `D:\beeofficeV\tools\push_github.ps1` |
| lightdb_project | `D:\lightdb_project\push_to_github.ps1` |

用法（脚本默认使用**脚本所在目录**的仓库）：

```powershell
# 默认：8 次重试，每次失败等待 5s（指数退避，最长 20s）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\push_to_github.ps1

# 自定义重试次数/间隔
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\push_to_github.ps1 -Retries 12 -Delay 10

# 只检查不推送
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\push_to_github.ps1 -DryRun

# 指定仓库/远端/分支，或跳过 tags
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\push_to_github.ps1 -RepoPath D:\beeofficeV -Remote origin -Branch main -SkipTags
```

脚本会：
1. 预检工作区、`origin` 是否存在、本地分支/HEAD/待推 tag 数（未提交改动只告警，不自动提交）；
2. 重试 `git push <remote> <branch> --tags`，失败自动分类：
   **3=认证失败**、**4=网络失败**、**5=远端有分叉/非快进**（提示 `git pull --rebase`）、**2=预检失败**；
3. 用 `cmd /c` 捕获 git stderr，避免 PowerShell 的 `NativeCommandError` 噪声；
4. 全部失败时打印离线裸仓库备份命令，退出码非 0。

**本机实测**（2026-10-22）：
- DryRun 正常（BeeOffice：HEAD `8dc1afa`、8 个 tag；lightdb：HEAD `3fa9f64`、32 个 tag）；
- 对 `lightdb_project` 真跑 1 次：`Failed to connect to github.com:443 after 21122 ms`，
  脚本正确判为**网络错误**并退出码 4（与 BeeOffice 相同的网络限制，不是脚本/权限问题）。
- 网络恢复后，直接运行脚本即可；若缺少凭据，脚本会以退出码 3 提示先 `gh auth login`
  或配置 PAT / Git Credential Manager。
