# BeeOffice 架构 RFC（草案）

状态：**Approved（定稿）**  
日期：2026-11-18  
批准人：项目负责人  
生效：Phase 0 起  
目标：用 6 个月逐步收敛文档模型与依赖边界，禁止大爆炸重写。

## 1. 分层

```text
ui/        Qt 控件、Ribbon、对话框
app/       用例、命令、撤销、事务
domain/    文档模型、规则、对象模型
adapters/  DOCX/XLSX/PPTX/PDF、WPS/MS 验收
infra/     存储、日志、配置、AI、网络
```

## 2. 依赖规则

- domain 不依赖 Qt；
- ui 不直接读写文件；
- adapter 不互相调用；
- 禁止跨 Mixin 访问私有属性；
- 新功能只允许写 domain/app；
- 元数据 schema 版本化，解析必须容错。

## 3. 文档模型 v1

- 三模块统一 `Document` 根对象；
- 节点：段落/表格/图片/形状/图表/占位符/批注/域；
- 每个节点有稳定 id、样式、位置、来源；
- 导入导出只通过 adapter；
- 撤销/重做基于命令与快照混合。

## 4. 迁移策略（绞杀者模式）

1. 新功能写新服务；
2. 旧 Mixin 只做转发；
3. 每两周迁移一个模块；
4. 迁移前必须有契约测试；
5. 迁移后删除旧路径，禁止双写。

## 5. 元数据 schema

```text
beeoffice-shapes/v1
beeoffice-chartobj/v1
beeoffice-master/v1
beeoffice-table-style/v1
beeoffice-anim/v1
```

要求：

- 带版本号；
- 未知字段保留；
- 解析失败不崩溃；
- 外部编辑后仍可恢复。

## 6. 测试策略

- domain 单测 70%
- adapter 契约测试 20%
- UI 冒烟 10%
- 真实语料/WPS/MS 验收必跑

## 7. 决策记录

- ADR-001：冻结功能，先修地基
- ADR-002：不重写，绞杀者迁移
- ADR-003：真实语料优先于 mock
- ADR-004：发布必须签名与干净机验收

## 8. 决议（定稿）

- 统一 Document 粒度：按模块 Document + 通用 Node，不做单一巨型模型；
- 撤销：命令为主，批量导入/导出使用快照；
- adapter 契约测试：pytest + 真实样本 + OOXML 校验；
- schema 校验：`tools/ooxml_check.py` 入发布门禁，后续升级 Open XML SDK。

## 9. 接口契约（冻结）

```text
Document.load(path) -> Document
Document.save(path) -> None
Document.to_ast() -> Node
Adapter.import(path) -> Node
Adapter.export(Node, path) -> None
```

规则：

1. Adapter 不得弹 UI，不得依赖 Qt；
2. 所有文件读写必须经过 Adapter；
3. 失败必须抛出可诊断错误，禁止静默降级；
4. 元数据未知字段必须保留；
5. 新增节点类型必须同时提供导入/导出/测试。

## 10. 迁移验收

每个模块迁移到新服务层前必须满足：

- 旧路径与新路径输出等价（差异报告）；
- 契约测试通过；
- 真实语料往返不下降；
- 无新增 P0/P1 缺陷；
- 文档记录迁移前后责任边界。

## 11. 明确不做

- 不重写全部 UI；
- 不引入第二套文档模型；
- 不在迁移期并行开发新功能；
- 不允许 Adapter 互相调用；
- 不接受“先上线再补测试”。

## 12. 批准与复审

- 本 RFC 自 2026-11-18 起生效；
- 每阶段门禁复审一次；
- 变更需新增 ADR，不得直接修改本 RFC 的冻结条款。
