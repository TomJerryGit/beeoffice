## 1. P0 止血（已发布 v5.0.12）

### 1.1 关主窗口不再静默丢数据（审计 §4.3 G1）

**改动**：`beeoffice/app.py`
- 新增 `_dirty_tabs()`：遍历所有标签收集"有未保存修改且参与检查"的标签；
- 新增 `_ask_close_tab()`：逐标签询问「保存 / 不保存 / 取消」（独立方法，便于测试）；
- 新增 `_confirm_close_all_tabs()`：用户取消或保存失败 → 中止关闭；
  对"从未保存到文件"的文档选「不保存」时，关闭前写一份草稿（下次启动可恢复）；
- `closeEvent()` 先执行上述检查，`event.ignore()` 中止。

**回归**：`tests/fidelity/test_close_unsaved_guard.py`（8 条）
- 干净窗口不弹框；取消 → `closeEvent.ignore()` 且不留草稿；
- 不保存 → 草稿目录有该文档且内容可读；
- 保存失败 → 中止关闭；保存成功 → 允许关闭；
- 检查逻辑自身异常 → 也中止关闭（宁可关不掉，不能丢数据）。

### 1.2 自动保存覆盖所有标签（审计 §4.3 G3）

**改动**：`app._autosave()` 从 `currentWidget()` 改为遍历 `tab_manager` 全部标签；
有路径的调 `save()`，无路径的写草稿；成功保存后清草稿并更新初始内容。

**回归**：同文件后 2 条 —— 当前页是 A、后台 B 也被保存；无路径标签不会触发 `save()`（避免弹另存框）。

### 1.3 主文档保存原子化（审计 §4.3 G2）

**改动**：
- `beeoffice/utils.py` 新增 `atomic_replace(target)` 上下文管理器：
  同目录、**保留扩展名**的临时文件 → 正常结束后 `fsync` + `os.replace`；
  任何异常删除临时文件并继续抛出；不用 `tempfile.mkstemp`（项目已实测其可能无限阻塞）。
- 接入点：
  - 蜜写 `.md`：`_write_md`（替代原先 `open(path,"w")` 的截断式写）；
  - 蜜写 `.docx`：`_rich_to_docx` 的 `doc.save`；
  - `bee_export.export_to_docx` / `export_html_to_docx`（beecmd 与 GUI 导出共用）；
  - 蜜算 `.xlsx`：`_write_xlsx` 的"数据写入 + 样式回贴"整体在临时文件上完成；
  - 批注/书签旁挂 `.comments.json` / `.bookmarks.json`：`atomic_write_json`。

**回归**：`tests/fidelity/test_atomic_saves.py`（6 条）
- 原子替换成功/失败语义、临时文件不残留；
- `export_to_docx` 在 `Document.save` 中途失败 → 原 docx 字节不变；
- `_write_xlsx` 在样式阶段失败 → 原 xlsx 字节不变；
- 正常 xlsx 保存后 openpyxl 可读回数据；
- `_write_md` 失败 → 原 md 内容不变。

**兼容性**：`tests/regression/v5/test_v505_permission_error.py`（文件被占用时
仍走"友好提示 + 返回 False"）与 `test_v505_comment_bookmark_persistence.py` 均通过。

## 2. P1 正确性与首次体验（tag 之后，未打包）

### 2.1 公式引擎 Excel 兼容语义（审计 §3.3 L2/L3）

**问题**（分析实测）：
- `=IF(A1=1,…)`、`=IF(A1<>2,…)`、`=AND(A1=1,B1=2)` 直接 `#ERROR`（只认 Python `==`/`!=`）；
- `=SUM(A1:A8)/2` 返回**公式文本字符串**、`=SUM()+SUM()` **静默返回 0**；
- `=SUM(A1:A2)+SUM(B1:B2)` 被贪婪正则误判成"一次 SUM 调用"而返回 0。

**改动**：`beeoffice/plugins/beesheet_engine.py`
- 新增 `_normalize_excel_operators()`：引号外的 `<>`→`!=`、单个 `=`→`==`
  （`<=/>=/!=/==` 不受影响；字符串字面量不处理）；
- 新增 `_single_call_parts()`：按括号配对判断"整个表达式是否单次函数调用"，
  替换原先的贪婪正则（同时用于顶层与跨表兜底路径）；
- 新增 `_substitute_functions()` / `_eval_arithmetic()`：先把表达式里的函数调用
  由内向外求值并替换为字面量，再走 AST 白名单；字符串内的函数/引用不动；
  函数返回错误值（`#N/A` 等）或求值异常 → 明确的 `#ERROR`，不再退化成公式文本；
- `!=` 不再被误判为跨表引用 `!`；
- `ROUND` 第一个参数改用 `_eval_arg`（支持 `ROUND(SUM(...)/4,0)`），
  并按 Excel 的 `.5 远离零` 舍入语义（Python `round(2.5)=2`，Excel `ROUND(2.5,0)=3`）。

**回归**：`tests/fidelity/test_formula_excel_compat.py`（26 条）：
条件运算符、函数结果运算、字符串字面量保护、错误传播、注入仍被拦截；
连同 `tests/unit/test_beesheet_engine_v51.py`（113 条）与
`tests/regression/p0/test_p0_05_*.py`（安全边界）共 **181 条全部通过**。

### 2.2 首次打开 DOCX 性能（审计 §4.4）

**分段剖析**（cProfile，5 万字真实文档，A 级实测）：

| 阶段 | 优化前 | 优化后 |
|---|---:|---:|
| `import_from_docx` | **3.58 s** | **0.43 s** |
| `read_docx_extras` | **4.91 s** | **0.26 s** |
| 端到端首次打开（5 万字） | **5.85 s** | **0.83 s** |
| 端到端首次打开（2.6 MB 带图） | **1.79 s** | **0.83 s** |
| 热开（2.6 MB） | 0.63 s | **0.26 s** |

**根因（不是猜的）**：python-docx 的 `paragraph.style` 每次访问都会调用
`styles.default_for()`，遍历**全部 772 个样式**做 XML 属性解析。
5 万字文档 1,090 次调用 → 2,000,000+ 次函数调用，占导入耗时 80% 以上。

**改动**：`beeoffice/plugins/bee_export.py`
- 新增 `_style_id_to_name(doc)`：一次性构建 `styleId → 样式名` 映射
  （并用 python-docx 的 `BabelFish.internal2ui` 保留"heading 1 → Heading 1"翻译，
  否则标题识别会失效 —— 这个坑被 2 条既有测试当场抓住）；
- 新增 `_paragraph_style_name(para, style_map)`：直接读 `w:pPr/w:pStyle/@w:val`
  再查表，O(1)；
- `import_from_docx` / `_read_paragraph_styles` 改用它，导入结果（标题/列表/样式记录）
  与原先一致 —— 由 176 条 DOCX 导入/保真测试验证。

**进度反馈**：`app._open_docx_file` 的后台导入完成、进入主线程渲染前，
状态栏更新为「正在渲染 Word 文档…」（两阶段提示）。

## 3.5 阶段③预演：无 GUI 的 beecmd 批量流水线（可复跑）

用 `beecmd batch` 在**不启动界面**的情况下跑通一条最小真实流水线
（源码见 `docs/示例-beecmd批量流水线.md`，产物在 `_ptmp/analysis/stage3_demo/`）：

```
7 条任务全部成功（7/7，exit 0）：
1. xlsx → csv
2. csv → xlsx（往返）
3. verify(源 xlsx, 往返 xlsx)          → 0 处不一致
4. md → docx
5. verify(md, docx)（词元级）          → 0 处不一致
6. md → pdf                            → 产出 1 个 PDF
7. md → beshow
审计流水：audit.jsonl 7 条（含每条 job / ok / exit_code / 时间戳）
```

**它证明了什么**：
- 表格与文档转换**可在无 GUI、无 Qt 窗口的情况下被脚本调用**；
- `verify` 的"0 差异"是逐格/词元级校验，不是"文件存在即成功"；
- 失败会如实返回非 0 退出码并写入审计流水（本次为全成功，失败路径有既有测试）；
- 这条链路就是"本地优先、可编程、可审计"定位的最小可验证形态。

**它还没证明什么**（下一步）：
- 没有外部真实用户参与，也没有 50 份真实文档的损失率统计；
- 模板化（合同批量转 PDF、Excel 多表汇总、演示批量导出）尚未做；
- 没有 `audit.jsonl` 的失败注入演练（单条失败不中断整批已有代码与测试，但未在本次演示）。
