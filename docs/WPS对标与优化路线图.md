# WPS 对标与 BeeOffice 优化路线图

> 基准：本机 WPS Office **12.1.0.29161**（含会员），2026-10-18 实测。
> 对照：BeeOffice 5.3.1（提交 `aa9c421`）。

## 一、实测记录

| 项 | 值 |
|---|---|
| 版本 | 12.1.0.29161（另存 12.1.0.28505 旧版） |
| 安装路径 | `C:\Program Files (x86)\WPS Office\12.1.0.29161\office6` |

### 1.2 观察到的主界面结构

- 顶部：WPS 365 / 管理后台 / 全局搜索（文件、模板、文库、应用、技巧）

**WPS 文字**（`docs/wps-writer.png`）：

- 标签页：文件 / 开始 / 插入 / 页面 / 引用 / 审阅 / 视图 / 工具 / **会员专享** / **WPS AI**
- 开始区：格式刷、粘贴、字体（四号）、B/I/U/上下标、文字效果、颜色、样式、段落（对齐/行距/项目符号/编号/缩进/边框/底纹）
- 左侧导航窗格：目录 / 章节 / 书签 / 查找和替换，含 **AI 识别目录** 按钮

### 1.3 实测限制（如实说明）

WPS 的主窗口由自绘框架（`KPromeMainWindow`）渲染，**UI Automation 只能读到 91 个命名控件**，
功能区按钮全部没有 automation 名称；合成鼠标点击（`mouse_event` / `SendInput`）被 WPS 忽略，
截图前后字节一致。因此**会员专享标签页内的具体条目未能实测展开**，
下述会员权益来自官方权益说明与界面可见入口。

## 二、WPS 会员功能盘点

按"付费价值"分层（来源：[WPS 会员功能盘点](https://www.wpschina.net/details/wps-member.html)）：

### 2.1 绝对刚需型

| 功能 | 免费版 | 会员 |
|---|---|---|
| PDF 转 Word / Excel / PPT | 有次数限制 | 限额或不限次 |
| PDF 合并 / 拆分 | ❌ | ✅ |
| 文档修复 | ❌ | ✅ |
| OCR（图片转文字） | 有限额度 | 更高额度 |

### 2.2 场景依赖型

| 功能 | 免费版 | 个人会员 | 超级会员 |
|---|---|---|---|
| 云空间 | 1 GB | 100 GB | 200 GB+ |
| 模板 VIP | ❌ | ✅ | ✅ |
| 全文翻译 | ❌ | ✅ | ✅ |
| WPS AI 调用次数 | 有限 | 更多 | 更多 |

### 2.3 保险型 / 重度型

- 批量处理（批量转换、批量打印、批量加水印/页码）——超级会员
- 数据恢复——超级会员

### 2.4 WPS AI 的能力面

| 模块 | 能力 |
|---|---|
| 文字 | 内容生成（大纲/正文）、润色（改写/扩写/缩写）、摘要、文档问答 |
| 表格 | 自然语言生成公式、数据清洗建议 |
| 演示 | 一键生成 PPT、排版优化、演讲稿生成 |

### 3.1 BeeOffice 的相对优势（不要丢掉）

- **本地优先、无需登录**：不强制账号，不弹会员推广
- **BYO AI Key**：用户自己的 Key 直连，文档不出本机
- **完全开源可改**：MIT，插件市场可扩展
- **无功能墙**：所有已实现功能不设付费门槛

## 四、优化路线图

排序依据：**用户可感知价值 ÷ 实现成本**，并优先复用已装依赖。

### P0：1–2 周，投入产出比最高

#### P0-1 PDF 页面工具集（2–3 天）

- 合并多个 PDF、按页拆分、提取指定页、删除页、旋转、重排
- 依赖：PyMuPDF（已装）
- 形态：PDF 插件内新增"页面"工具条 + 缩略图列表
- 风险：低（纯本地操作，无格式还原问题）

#### P0-2 批量处理面板扩展（3–5 天）

- 现有 `_run_batch_convert` 只支持 docx↔md；扩展为：
  - 图片 → PDF
  - PDF → 图片（PNG/JPG）
  - 批量加水印 / 加页码
  - 批量导出 PDF（docx/md/pptx/xlsx 统一入口）
- 依赖：PyMuPDF、python-docx、python-pptx（已装）
- 风险：低-中（需处理部分失败与命名冲突）

#### P0-3 翻译功能落地（2 天）

- 把 `beeoffice/ai_assist.py::simple_translate` 的占位实现替换为真实调用
- 支持：选中段落翻译 / 整篇翻译（分段送 API，保留格式）
- 复用现有 AI 配置（`ai_api_key`），无 Key 时明确提示而非静默失败
- 风险：低

### P1：3–6 周

#### P1-1 OCR 集成（5–7 天）

- Tesseract（Apache-2.0，可离线）或 PaddleOCR
- 场景：扫描件 PDF → 可搜索 PDF；图片 → 文字插入蜜写
- 打包体积 +30–80 MB（语言包）
- 风险：中（中文识别质量、打包体积）

#### P1-2 PDF → Word/Excel 转换（5–8 天）

- 方案 A：LibreOffice headless（MPL-2.0，需用户装 LO）
- 方案 B：`pdf2docx`（**AGPL-3.0**，与 PyMuPDF 同类风险）
- 建议 A：许可证更干净，且 LO 转换质量对纯文字 PDF 足够
- 必须做**质量兜底**：转换失败/乱版时提示"建议保留 PDF 原件"
- 风险：中-高（用户预期管理）

#### P1-3 模板包机制（3 天）

- 模板导出为 `.beetpl`（zip：docx/pptx + 元数据 + 预览图）
- 支持从文件夹批量导入、预览图展示
- 风险：低

### P2：暂缓，需要明确取舍

| 项 | 结论 | 理由 |
|---|---|---|
| 文档修复 | **不做** | 成功率不可控，损坏文档的解析极易引入新 bug |
| 团队协作/知识库 | **不做** | 云端产品形态，与"本地优先"定位冲突 |
| 云空间扩容 | **不做** | 用户自带 WebDAV/OneDrive 更符合定位 |
| 模板商城 | **不做** | 内容生态，无法靠代码补齐 |
| VBA 兼容 | **不做** | 工程量巨大，自研宏已覆盖常见场景 |

## 五、许可证提醒

当前已依赖 **PyMuPDF（AGPL-3.0）**，分发二进制时需履行 AGPL 义务。
若再引入 `pdf2docx`（同为 AGPL）会扩大暴露面；**推荐 LibreOffice（MPL-2.0）**路线。

详见 `THIRD_PARTY_NOTICES.md`。

---

## 六、建议立即启动的三件事

1. **PDF 页面工具集**：用户每天都会用到，且零技术风险
2. **翻译落地**：已有占位桩，接上 API 即完成，投入 2 天
3. **批量面板扩展**：框架已存在，扩展成本低于新建

完成这三项后，BeeOffice 在"PDF 处理"与"批量操作"两个维度上，
对免费版 WPS 形成明确优势；与会员版的差距将集中在
**PDF→Office 转换质量**与**云端协作**两处——这两项建议明确列为"不做"。
