## 3. 蜜写渲染优化（2026-11-04）

### 根因

`set_markdown` 逐块 `insertBlock/insertText` 时，每次 `textChanged` 都触发
`_update_status_bar()`，而状态栏用 `count_words()` 对整篇文本做正则统计。
200 段文档触发 **2599 次全文统计**，呈 O(n²)，profile 下耗时 27.6s。

### 修复

在批量渲染期间对 `rich_editor.blockSignals(True)`，渲染完成后只更新一次状态栏：

- `beeoffice/plugins/beewrite_mode_mixin.py`
  - 新增 `_set_rich_markdown()`
  - `set_content()` / `_switch_mode()` 统一走该入口
- 新增回归测试 `tests/qt/test_beewrite_bulk_render.py`
  - 断言 100 段批量渲染只触发一次 `count_words`

### 结果

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| Markdown → 富文本（200 段） | 12,119 ms | **87.2 ms** |
| `set_content`（Markdown） | — | 12.0 ms |
| 蜜写编辑器首次创建 | — | 2,807 ms |
| 蜜写总计（创建+设置+渲染） | 12,119 ms | **2,907 ms** |
| 状态栏全文统计次数 | 2,599 | 1 |

优化后重跑基线（同轮拆分）：

| 指标 | 结果 |
|---|---:|
| 导入 `beeoffice.app`（中位数） | 1,871.0 ms |
| BeeApp 启动 + 懒加载 | 754.4 ms |
| 蜜算：50,000 单元格载入 | 135.9 ms |
| 蜜算：CSV 导出 | 27.8 ms |
| 蜜演：30 页预览 | 35.6 ms |
| 蜜演：PPTX 导出 | 386.2 ms |
| 操作后 RSS | 302.3 MB |

> 绝对值受机器负载影响明显；优化前后均在同一台机器、同一脚本下测量。

## 4. 发现

1. **蜜写 200 段渲染 12.1s** 是最大异常项，需 profile（Markdown 解析/富文本重建/撤销栈）；
2. 冷导入约 2.1s，影响首次启动体验；
3. 启动后 RSS 84MB，完成三类文档操作后涨到 304MB，需检查文档对象释放；
4. 其它操作（表格载入/CSV/PPTX）在 1s 级，可作为当前基线。
