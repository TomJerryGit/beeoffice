# BeeOffice 开发 / 优化 / 测试路线图（v5.4.5 之后）

日期：2026-11-12  
基线版本：v5.4.5（2026-11-12 已发布）  
依据：[软件分析审计评价-v5.4.5](软件分析审计评价-v5.4.5-2026-11-12.md)

## 1. 当前基线

```text
功能：BeeWrite / BeeSheet / BeeShow / PDF / 云同步可用
测试：1550 passed
覆盖：全仓约 66.5%，核心 12/12 = 100%
安全：高危模式 0，2 条 guarded eval
CI：安装/卸载冒烟已通过（Windows Server）
发布：v5.4.5 已发布，未签名
```

主要缺口：

1. 安装包未签名；
2. 未做 Win10/11 干净机验收；
3. CI 中全量测试不阻塞，安全/覆盖率未进门禁；
4. 依赖无锁文件/SBOM；
5. GUI 分支覆盖不足，发布后才发现拆单元格崩溃；
6. 大模块、Mixin 耦合、宽泛异常；
7. Win11 未验证。

## 2. 路线图总览

| 里程碑 | 目标 | 预计 | 优先级 |
|---|---|---|---|
| **M1 可信发布门禁** | 签名 + 干净 Win10 + CI 硬门禁 | 1–2 周 | P0 |
| **M2 质量基线** | 可复现依赖、静态检查、分支覆盖 | 2 周 | P1 |
| **M3 v5.5 Beta** | GUI 关键路径回归、覆盖率 70%、重构启动 | 3–4 周 | P1 |
| **M4 Win11 决策** | 有环境则验证，否则明确不支持 | 依赖环境 | P2 |

> M1 未完成前，不建议把版本称为“稳定版”；可以发布，但必须保留未签名/未验收声明。

## 3. 分阶段任务

### M1：可信发布门禁（P0，1–2 周）

| 工作项 | 验收标准 | 依赖 |
|---|---|---|
| 采购/配置代码签名证书 | `Get-AuthenticodeSignature` 为 Valid | 证书采购 |
| 签名 ZIP/安装包 | 安装包与 ZIP 均签名 | 证书 |
| 干净 Win10 22H2 验收 | 安装/启动/卸载/快捷方式/核心功能通过 | 云 VM 或新机器 |
| CI 硬门禁 | main 受保护；全量测试/安全扫描/核心覆盖率必须通过 | GitHub 设置 |
| 发版清单自动化 | tag 前必须过 build + test + scan + install smoke | CI |
| Release 说明模板 | 固定披露未验证项与哈希 | — |

**完成定义**：v5.4.6（或 v5.5.0）发布时，安装包有有效签名，且在干净 Win10 上完成验收；否则继续标 Beta/未验收。

### M2：质量基线（P1，2 周）

| 工作项 | 验收标准 |
|---|---|
| 依赖锁定 | `requirements.lock` 或 uv/pip-tools 锁文件；构建可复现 |
| SBOM | 生成 CycloneDX/SPDX SBOM |
| 依赖漏洞扫描 | `pip-audit` 无高危，或记录豁免理由 |
| 静态检查 | ruff 基线清零（至少 F/E9）；mypy/pyright 对核心模块启用 |
| 分支覆盖 | 核心模块行覆盖 100% + 分支覆盖 ≥90%；全仓 70% |
| 宽泛异常治理 | 核心模块不再吞异常；GUI 至少记录上下文 |
| 安全扫描进 CI | `security_scan.py` 高危 >0 阻止合并/发布 |
| 覆盖率门槛进 CI | `coverage_gate.py` 核心 100% 阻止回归 |

### M3：v5.5 Beta（P1，3–4 周）

重点不是继续堆覆盖率，而是补**用户关键路径**：

| 优先级 | 工作项 | 验收 |
|---|---|---|
| P1 | 富文本表格：合并/拆分/行列表格/图片单元格 | 真实 Qt 事件循环测试通过 |
| P1 | 文档导出：DOCX 表格/图片/页眉页脚/分页 | 导出后用 python-docx 回读校验 |
| P1 | BeeSheet 导入/填充/筛选/条件格式 | 关键 GUI 路径回归 |
| P1 | BeeShow 视频/同步/AI 失败路径 | 有超时/断网/无依赖用例 |
| P2 | 全仓覆盖率 66.5% → 70% | CI 显示 |
| P2 | 启动/打开大文件/导出性能基准 | 有基线数据，无退化 |
| P2 | 崩溃日志/错误反馈隐私策略 | 文档 + 开关 |
| P3 | 拆分 `app.py` / `beesheet_engine.py` / `beewrite_rich_editor.py` | 单文件 ≤800 行，行为不变 |
| P3 | 插件来源/签名校验 | 插件市场安装前校验 |

### M4：Win11（P2，条件触发）

- 需要 VMware 17+/Hyper-V/云 VM/新机器；
- 验证 TPM/Secure Boot、安装、启动、WebEngine、快捷方式；
- 通过后更新系统要求；未通过则明确写“Win11 不支持/未验证”。

## 4. 发版硬门禁（建议）

每次发布必须：

```text
[ ] 版本号 + CHANGELOG
[ ] 全量 pytest 通过（不允许 continue-on-error）
[ ] 核心覆盖率 100%
[ ] 全仓覆盖率不低于基线（当前 66.5%）
[ ] security_scan 高危 0
[ ] 构建成功 + 新 ZIP/安装包 + SHA-256
[ ] ZIP testzip OK
[ ] 安装/卸载冒烟成功
[ ] 安装包签名有效（M1 后）
[ ] 干净 Win10 验收记录（M1 后）
[ ] Release 说明披露限制
[ ] 资产上传并核对大小/哈希
```

## 5. 测试策略调整

- 不再把“覆盖率数字”作为唯一目标；
- 核心算法/数据/协议：行覆盖 100% + 分支覆盖；
- GUI：优先关键路径，不追全量 100%；
- 每个修复 bug 增加“失败复现 → 修复 → 回归”用例；
- 发布前跑真实 Qt 事件循环测试，不只用 mock/dialog.exec 替换；
- 安装/卸载/升级单独作为发布冒烟。

## 6. 风险与不承诺

| 风险 | 处理 |
|---|---|
| 无签名证书 | 继续标 Beta/未签名；不称稳定版 |
| 无干净机环境 | 云 VM 或新机器；否则不写“干净机通过” |
| Win11 环境不足 | 明确“未验证”，不阻塞 v5.5 |
| 8 GB 宿主限制 | 不在本机硬搭 VM；优先云 VM |
| 覆盖率提升边际递减 | M3 后以缺陷/性能/重构为主 |
| 大重构风险 | 行为不变 + 分批合入 + 回归测试 |

## 7. 建议时间线

```text
第 1 周：M1 证书/CI 门禁 + 云 Win10 VM 准备
第 2 周：干净机验收 + 签名发版
第 3–4 周：M2 依赖锁定/SBOM/静态检查/分支覆盖
第 5–8 周：M3 GUI 关键路径 + 覆盖率 70% + 性能基线
第 9 周起：重构/插件安全/Win11 决策
```

## 8. 结论

下一步不应继续只刷 GUI 覆盖率，而应先完成 **M1 可信发布门禁**；否则功能继续增加，发布信任链仍然是短板。M1 完成后再进入 M2/M3，路线更稳。
