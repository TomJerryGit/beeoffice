## 2. 性能基线

命令：

```powershell
python tools/perf_baseline.py --out _ptmp/analysis/s3_perf_baseline.json
```

| 指标 | 结果 |
|---|---:|
| 导入 `beeoffice.app`（3 次中位数） | **2101.5 ms** |
| BeeApp 窗口创建 + 懒加载 | **672.7 ms** |
| 启动后 RSS | 83.9 MB |
| 蜜写：200 段新建 + 富文本渲染 | **12119.1 ms** ⚠️ |
| 蜜写：DOCX 导出 | 2787.5 ms（37,856 B） |
| 蜜算：50,000 单元格载入 | 618.2 ms |
| 蜜算：CSV 导出 | 91.3 ms（243,954 B） |
| 蜜演：30 页预览 | 699.7 ms |
| 蜜演：PPTX 导出 | 1188.1 ms（53,199 B） |
| 操作后 RSS | 304.4 MB |

## 3. 发现

1. **蜜写 200 段渲染 12.1s** 是最大异常项，需 profile（Markdown 解析/富文本重建/撤销栈）；
2. 冷导入约 2.1s，影响首次启动体验；
3. 启动后 RSS 84MB，完成三类文档操作后涨到 304MB，需检查文档对象释放；
4. 其它操作（表格载入/CSV/PPTX）在 1s 级，可作为当前基线。

## 4. 下一步

- 对 `BeeWriteEditor.set_content` + `_switch_mode("rich_text")` 做 profile，目标 < 2s/200 段；
- 加“打开→保存→重开”语料回归，覆盖真实 DOCX/XLSX/PPTX；
- 监控 RSS 增长，确认关闭文档后释放；
- 将本基线纳入每次发布前对比（只报告回退，不阻塞）。
