# R2 spike：中文排版"避头尾"可行性（2026-10-14）

> 目的：**只回答"能不能做、要不要做"**，不实现。原计划 0.5 人日 spike。
> 方法：排版后读 `QTextLayout` 的实际断行，统计"行首出现收尾标点 / 行尾出现开启标点"的违规数。
> 关键前提：**仪器必须先被证明有效**（见下文三次仪器故障）。

## 0. 重要更正（2026-10-15，实现阶段实测）

本文件 §3 最初写的是"避尾可以用 `U+2060` 粘住 → R2 缩小为'只做避尾'（≈2 人日）"。
**那个结论是错的**：它是从"避头"实验**推断**出来的，我当时**没有真正测过避尾的处理效果**。

实现阶段补测（判据见 §4 的坑 #3）：

| 插入的标记 | 避尾违规（21 个宽度合计） | 判定 |
|---|---|---|
| 不处理（基线） | 21 | — |
| `U+2060` WORD JOINER | **21** | ❌ 与基线相同 → **Qt 不认** |
| `U+200D` ZWJ | **21** | ❌ 与基线相同 |
| `U+FEFF` ZWNBSP | 21 | ❌ 与基线相同 |
| `U+00A0` 不换行空格 | 21 | ❌ 与基线相同 |
| `U+2007` 数字空格 | 21 | ❌ 与基线相同 |
| `U+200B` 零宽空格（**负对照**） | 316 | 它提供断行机会 → 证明仪器能分辨差异 |

**新结论：Qt 5/6 的富文本断行不认这些"两侧禁断"的行断类（`WJ`/`ZWJ` 都没有实现到
这条 CJK 路径上），所以避尾无法用插入文本标记实现。** 要做得自己实现行断
（自定义 `QAbstractTextDocumentLayout`），成本远超收益且会牵动绘制与光标逻辑 → **不做**。

**实现被完整回退**（`beewrite_rich_editor.py` 回到原状）：
一个只改文本、零收益的方案是纯负担。仅保留 `beeoffice/plugins/kinsoku.py`
作为**实测证据模块**，并由 `tests/fidelity/test_r2_kinsoku_limitation.py`
当**金丝雀**钉住 —— 哪次 Qt 支持了，测试会失败并提醒"R2 可以重做"。

### 由此得到的 R2 最终结论
| 子项 | 结论 |
|---|---|
| **避头**（行首不收尾标点） | ✅ **Qt 自带**（默认 0 违规）→ 不需要做 |
| **避尾**（行尾不开启标点） | ❌ **Qt 做不到**（5 种标记实测全部无效）→ 不做，留金丝雀 |
| **标点挤压** | ❌ 无现成开关，需自定义 layout → 不做 |

**R2 因此从"2–3 人日"变为"0 人日（已判定不做）"**，并且这个"不做"是**有数据支撑的**。

## 1. 结论（先说结果）

| 规则 | Qt 默认行为 | 负对照（人为造断点） | 判定 |
|---|---|---|---|
| **避头**（`，。）》` 不出现在**行首**） | **0 违规** | 115 / 237 处 | ✅ **Qt 自带，不用做** |
| **避尾**（`（《「` 不出现在**行尾**） | **21 违规** | 316 / 537 处 | ❌ Qt 不做；且**插入标记也修不好**（见 §0） |
| **标点挤压**（连续标点半角化） | — | — | ❌ `QTextOption` 无相关开关，需自定义 layout，**不做** |

- 两处测量一致：**裸 `QTextDocument`** 与**真实蜜写编辑器**（`RichTextEditor`）结论相同。
- 负对照的意义：主动插入 `U+200B`（零宽空格＝显式断行机会）来**制造违规**；
  能报出违规才说明检测器有效。**没有负对照的"0 违规"什么都不能证明。**

## 2. 两次仪器故障（这才是本次 spike 最有价值的部分）

| 版本 | 现象 | 真相 |
|---|---|---|
| v1 | 默认/U+2060 都是 **0 违规** | **仪器坏了**：读 `block.layout().lineCount()` 前没强制触发布局 → 行列表**为空**；`violations([])` 当然是 0 |
| v2 | 修了布局，仍 **0 违规** | **测试构造导致"不可能失败"**：文本 33 字一循环、行宽恰好每行 12 字，而 `12n ≡ 标点位置 (mod 33)` **无解** → 断点永远撞不上标点 |
| v3 | 改成"标点在每个位置"+ 负对照 | ✅ 仪器自证有效（对照报出 115 处），默认 0 → **可信结论** |
| v4 | 避尾的负对照报 **0** | **对照本身失效**：插在标点后的 `U+200B` 成了行末"最后一个字符"，`ln[-1] in OPENING` 判不到 → 判据改为**先剥离零宽字符**再看首尾 |

> 教训与项目既有纪律一致：**"0 违规"这类好消息必须先证明仪器能报出违规**。
> 前两版都会得出"Qt 已经很完美"的错误结论，从而把 R2 直接砍掉 —— 那是**基于坏仪器的错误决策**。

## 3. 避尾：为什么最终**不做**（曾经以为"插 U+2060 就行"）

原本设想：在开启标点后插 `U+2060`（word joiner）粘住后一个字。**实测无效**（见 §0 表）：
Qt 的断行不认这些行断类，5 种候选标记插进去后违规数**与基线一模一样**。

**唯一能用的替代是"不换行空格"这类标记**——但它们**有宽度**，会在每个开启标点后
多出一个空隙（中文排版里就是错的）；而真正的做法（把标点与后字作为一体移动）
需要**自定义行断**。

**如果要真做**（仅供参考，不建议）：得实现 `QAbstractTextDocumentLayout` 子类，
自己算断行点、自己画每一行 —— 代价是编辑器全部绘制/光标/选区逻辑都要跟着改，
风险远大于"行尾偶尔出现一个（"这个观感问题。**决定不做**，并留金丝雀测试提醒未来。

## 4. 三次仪器故障（这才是本次 spike 最有价值的部分）

| 版本 | 现象 | 真相 |
|---|---|---|
| v1 | 默认/U+2060 都是 **0 违规** | **仪器坏了**：读 `block.layout().lineCount()` 前没强制触发布局 → 行列表**为空**；`violations([])` 当然是 0 |
| v2 | 修了布局，仍 **0 违规** | **测试构造导致"不可能失败"**：文本 33 字一循环、行宽恰好每行 12 字，而 `12n ≡ 标点位置 (mod 33)` **无解** → 断点永远撞不上标点 |
| v3 | 改成"标点在每个位置"+ 负对照 | ✅ 仪器自证有效（对照报出 115 处），默认 0 → **可信结论** |
| v4 | 避尾的负对照报 **0** | **对照本身失效**：插在标点后的 `U+200B` 成了行末"最后一个字符"，`ln[-1] in OPENING` 判不到 → 判据改为**先剥离零宽字符**再看首尾 |
| **v5（实现阶段）** | ZWJ/U+00A0 测出 **0 违规**，看似"修好了" | **判据漏剥插入的标记**：`strip` 当时不清 `U+200D`，于是"行末是零宽 ZWJ"被当成"末字符不是开启标点" → **假的 0**。把标记也剥掉后：21 = 基线 → 无效 |

> 教训反复同一条：**"好消息"必须先证明仪器能报出坏消息**。
> 本项前后出现过 **5 次"看起来已经达标/已修好"，其中每一次都来自坏仪器或坏判据**。
> 因此 `beeoffice/plugins/kinsoku.py` 的判据（`kin_violations`）**自带剥离逻辑**，
> 并且金丝雀测试里专门有一条测试钉住"带 ZWJ 的（ 行末仍应判为违规"。

## 5. 复现方式

可运行的复现（已入库，不再依赖临时脚本）：
`tests/fidelity/test_r2_kinsoku_limitation.py` —— 它包含
① 仪器自检（文本真的换行了）、② 负对照（`U+200B` 的违规必须多于基线）、
③ 5 种候选标记的对照（都与基线相同 = 无效）、④ 判据坑的钉子。

核心三步：
1. `QTextDocument.setPlainText(文本)` → `setTextWidth(宽度)` → **`documentLayout().documentSize()` 强制布局**；
2. 遍历 `block.layout().lineAt(i)` 取每行文本；
3. 统计行尾（**剥掉插入的标记后**）是开启标点的行数；
   **并且**用 `U+200B` 人为制造断点作为**负对照**，确认检测器能报出违规。
