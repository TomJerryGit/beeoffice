# BeeOffice 生产能力评估（实际评估版）

> 评估时间：本轮修复（11 批）完成之后 · 提交 `808424b`
> 依据：审计全文（`BeeOffice-功能真伪审计.md`）、逐批台账（`docs/baseline.md`）、
> 交付总结（`docs/交付总结-第1至11批.md`）、以及本评估**现场补查**的数据。
> **所有结论都标注证据等级；凡我没证据的都写在 §8 置信边界里，不做暗示。**

## 0. 评估口径（先说清楚我凭什么下结论）

**我实际做过的**（能复现）：
* 在本机**运行**了 813 条保真/单元测试、33 项门禁、静态检查；亲手复核了多段关键代码；
* 对每个修复项都做了**端到端实测**（读回文件、压缩包校验、真实 `BeeApp` 内发按键等）；
* 现场补查了规模、依赖可用性、打包声明、AI 端点等技术事实（见 §2）。

**我没做过的**（影响置信度，必须说明）：
* **没有跑过真实图形交互**：所有 Qt 测试都在 `offscreen` 下运行；**QtWebEngine 在本机无法初始化**，
  所以"蜜演"的渲染/播放/导出体验我**只能做类级与逻辑级校验**；
* **没有在真实用户文档上做长时间压力/兼容性测试**（保真语料库是最接近的代理）；
* **没有实测端到端交互延迟**（本轮只有"热路径确定性"门禁与计时门禁，没做人机响应测量）；
* **没有真实网盘/云环境**，云同步只用假 storage 验证引擎逻辑。

## 1. 结论

**一句话**：这是一套**功能面广、缺陷密度已被压到较低、并且把"数据安全"这条线守住了**
的办公套件；**可以用于受控场景的日常办公**（内部文档、表格处理、简单汇报、打印/导出），
但**还不具备"直接发给普通消费者、无人值守使用"的生产成熟度** ——
卡点不在功能数量，而在**打包交付链**、**未在真机验证的模块**、以及**外部服务依赖**。

| 场景 | 判定 | 依据（证据等级） |
|---|---|---|
| **内部小团队日常办公**（写文档、做表、打印、导出 DOCX/XLSX/PDF） | ✅ **可用**（建议先做 §7 清单） | 蜜写/蜜算核心链路有测试与门禁；格式/合并/批注/样式**写盘+读回**闭环已建立（**A**） |
| **桌面演示（蜜演）** | ⚠️ **有条件可用** | `.beshow` 保存链路已补（**A**），但 WebEngine 相关行为本机**无法验证**（**C**） |
| **数据交付/合规场景**（对外发版式文件、要"零丢失"保证） | ⚠️ **需评估** | 有保真语料库门禁与**损失报告**（**A**），但仍有已知降级项（见 §5） |
| **打包分发给最终用户** | ❌ **尚不可** | `beeoffice.spec` 缺 `beeoffice/data` → 打包版拼写白名单失效（**A**，本评估现场核出）；发布脚本未验证（**C**） |
| **协同/云同步作为卖点** | ❌ **不可对外承诺** | 同步引擎已实现且单测通过（**A**），但**无真实网盘验证**（**C**），且无冲突合并、无账号体系 |

## 3. 能力矩阵（按模块 × 生产判定）

### 蜜写（Word 替代）
| 能力 | 判定 | 证据 |
|---|---|---|
| Markdown/富文本双模式编辑、撤销/重做、查找替换 | ✅ 可用 | 快捷键歧义已修，真实 `BeeApp` 内验证（**A**） |
| 保存/另存 `.md`/`.docx`、覆盖原 `.docx` 前**留档并确认** | ✅ 可用 | 覆盖守卫有专门回归测试（**A**） |
| 导出 DOCX（页面设置/页眉页脚/合并/书签/相对图片） | ✅ 可用 | 导出与另存已统一到同一富文本路径（**A**） |
| 超链接、单元格多段落导出 | ✅ 可用 | 压缩包内外部关系 + `<w:hyperlink>` 实测（**A**） |
| 分页符/**真正的 Word 节** | ✅ 可用 | 导出后 section 数 = 2 实测（**A**） |
| 目录生成 | ✅ 可用 | 所见即所得插渲染结果，不再插 Markdown 源码（**A**） |
| 拼写检查（含技术词白名单） | ⚠️ 源码运行可用 / **打包版会降级** | 白名单文件未被 spec 打包（**A**，§5 R3） |
| AI 续写/润色/总结 | ⚠️ 取决于客户环境 | 未配 AI 时**先征求同意**再给本地规则结果并标注"不是 AI"（**A**） |

## 4. 八个生产维度评级

| 维度 | 评级 | 依据 |
|---|---|---|
| **数据安全（不丢数据）** | ✅ **好**（本轮重点） | 覆盖前留档与确认、`.`xls` 绝不原地写、格式写盘遇合并先保数据、自动保存**绝不替用户决定路径**、关标签提示未保存 —— 全部有回归测试（**A**） |
| **格式保真** | ✅ **好** | 保真语料库门禁 + 损失报告（含**位置**）+ 逐项读写回实测（**A**） |
| **稳定性** | ✅ **较好** | 33 门禁 + 1287 用例；已知 1 条计时抖动；QtWebEngine 相关文件在整套跑时会挂（**环境**问题）（**A**） |
| **性能** | ⚠️ **有保障但未量化 UX** | 有热路径**确定性**门禁与计时门禁（只报告）；本轮**没有**人机响应测量（**C**） |
| **依赖与打包** | ❌ **薄弱** | 运行依赖齐全，但 **spec 漏打包 `beeoffice/data`**、发布脚本未验证、`requirements.txt` 含被注释的依赖历史（**A/C**） |
| **失败模式（会不会"静默坏"）** | ✅ **已大幅改善** | 本轮专治"点了没反应"：缺库给提示、取消不产生副作用、失败不假装成功（**A**） |
| **安全** | ⚠️ **基础可用** | 移动端服务默认仅回环 + Host 校验；云同步有敏感文件白名单；但无账号体系、无加密存储（**B/C**） |
| **可维护性** | ✅ **好** | 三模块插件化、mixin 拆分、162 测试文件、门禁可扩展、F401 清零（**A**） |

## 6. 适用 / 不适用

**可以这样用**
* 小团队内部：写周报/纪要/合同草稿 → 导出 DOCX；做清单/核算/台账 → XLSX；简单汇报 → PPTX/PDF；
* 需要"**本地优先、数据不出内网**"的场景（AI 可指向内网 Ollama）；
* 作为**技术演示/教学**：代码结构清晰（插件化 + mixin + 162 测试文件 + 33 门禁）便于二次开发。

**不要这样用（会踩到已知短板）**
* ❌ 直接打包分发给外部最终用户（先修 R1/R5）；
* ❌ 把云同步当"网盘协同"卖（无账号体系、无冲突合并、未真机验证）；
* ❌ 把它当"PPTX 无损往返编辑器"（自有 `.beshow` 才是完整格式）；
* ❌ 强依赖 `.xls` 写入的流程；
* ❌ 在无人值守/无外网的机器上依赖 AI 功能。

## 7. 上生产前的最小验收清单（可执行）

```powershell
cd D:\beeofficeV
$env:QT_QPA_PLATFORM='offscreen'; $env:PYTHONPATH='D:\beeofficeV'

# 1) 功能与保真：全量测试 + 全部门禁必须全绿
python -m pytest tests/fidelity tests/unit -q -p no:cacheprovider -o log_file= --timeout=1500
python tools\check_gates.py
python -m ruff check beeoffice tests tools --select F821,F811,E9   # 必须通过
python -m ruff check beeoffice tests tools --select F401,TC005     # 必须为 0

# 2) 打包链（**当前会失败/降级，必须先修 R1**）
#    修法：在 beeoffice.spec 的 datas 里追加 beeoffice/data
python beeoffice\build_release.py            # 产出后：在干净机器安装并冒烟

# 3) 真机验证清单（本机无法覆盖，必须另找环境）
#    · 蜜演：播放/放映/PPTX+PDF 导出各人工过一遍
#    · 云同步：真实 WebDAV 双向演练（中文名、大文件、冲突、断网重试）
#    · 打印：真实打印机各缩放模式各一份
#    · AI：内网 Ollama + 无网两种情况
```

**必修（否则不建议对外分发）**：R1 打包缺数据文件 · R5 发布脚本验证 · R2 蜜演真机验证。

## 8. 未验证项与置信边界（不藏着）

| 未验证 | 为什么 | 对本评估的影响 |
|---|---|---|
| 蜜演 GUI/播放/导出体验 | 本机 QtWebEngine 无法初始化（FATAL） | §3 蜜演行整体降为 **C**，结论只能到"类级通过" |
| 真实网盘同步 | 无网盘凭据/环境 | 只能保证引擎逻辑正确 |
| `.xls` 真实解码 | 无 xlwt/LibreOffice 造夹具 | 只验了"引擎选择 + 接线" |
| 人机响应延迟 | 本轮未做测量 | §4 性能维度只给"有保障但未量化" |
| 长时稳定性（8 小时连续使用、内存增长） | 未做 | 未知；建议上线前做一次 |
| 打包产物在干净 Windows 上运行 | 未跑打包 | R5 明列 |
| 多语言/本地化完整性 | 审计指出 44 个缺失键（未修） | 非中文环境体验会降级 |
| 崩溃恢复/自动保存的**读取端** | 审计指出"有写无读"（未修） | 崩溃后可能拿不回自动保存内容 |

**边界总结**：本评估对"**逻辑正确性与数据安全**"的置信度高（有测试与门禁支撑，**A**）；
对"**在真实用户机器上的观感与兼容性**"置信度中低（**C**）。
两者不能互相替代 —— 上生产前请务必做 §7 第 3 步。
