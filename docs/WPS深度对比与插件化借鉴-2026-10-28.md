# BeeOffice vs WPS 深度对比与插件化借鉴方案（2026-10-28）

> 范围：BeeOffice v5.0.29（Windows 桌面版）vs WPS Office / WPS AI / WPS 365 公开能力。
> 证据边界：
> - BeeOffice 侧：仓库代码、测试（46 门禁 + 1630 条全量）、`docs/baseline.md` 实测性能、真实截图。
> - WPS 侧：公开官网/帮助文档/开放平台文档，**未登录 WPS、未做同机盲测**；涉及具体倍数的结论均标注来源或明确标为“待实测”。
> - 已有 294 行细节矩阵见 [WPS功能细节深度对标与首批提升-2026-10-22.md](WPS功能细节深度对标与首批提升-2026-10-22.md)，本文在其上补充 2026-10 的 UI/AI/CI 进展与**插件化落地方案**。

---

## 0. 一页结论

1. **基础编辑功能已“够用”，差距集中在生态与深水区**：文字/表格/演示的日常编辑，BeeOffice 已覆盖大部分；WPS 的护城河是 **云协作、模板/素材生态、AI 全家桶、PDF 全流程、JS 加载项/宏、移动多端**。
2. **性能不是最大短板，但有结构性差距**：BeeOffice 在真实路径上做过大幅优化（DOCX 打开 17.7s→1.38s、5 万字 5.85s→0.83s、蜜算滚动 337ms→23.6ms/帧、插件可用启动 555ms）；但 Python/Qt 架构在超大 PPTX 渲染、复杂表格公式重算、PDF 高保真编辑上仍难与 WPS 原生引擎长期抗衡。
3. **GUI/UI 已从“传统桌面软件”进入“WPS 式 Ribbon”阶段**（v5.0.22→v5.0.29），但仍是**外观层追平**：缺少真正的 Backstage 文件页、任务窗格框架、完整上下文选项卡、模板启动中心、命令搜索、AI 侧栏、动画面板/母版面板。
4. **最值得“做成插件”的不是再做一个 WPS 克隆**，而是把 WPS 中**高价值、可本地化、可审计**的能力插件化：AI 文档助手、PDF 工具箱、模板/素材中心、数据工具箱、演示美化/动画库、校对与格式体检、宏/脚本控制台、投屏遥控。
5. **不建议插件化**：云文档/多人实时协作、模板内容运营、PDF 转 Office/OCR/翻译全家桶、企业 365 平台——重资产、网络效应、合规成本高，和 BeeOffice “本地优先 + 可编程 + 可审计” 的定位冲突。
6. **当前插件系统（`Plugin` + `PluginManager`）只支持“整页编辑器插件”**（一个插件 = 一个 Tab），不足以承载 WPS 式加载项；需要升级为 **扩展点 API**（Ribbon/任务窗格/命令/事件/文档事务/权限）。
7. **建议路线**：先做 **插件扩展 API v1 + AI 任务窗格 + PDF 工具箱**（2–3 周），再做数据/设计/校对（3–4 周），最后做宏/脚本与局域网协作/投屏（3–4 周）；每阶段保持 46 门禁 + 全量测试 + CI artifact 绿。

## 2. 性能对比

### 2.1 BeeOffice 已有实测（来自 `docs/baseline.md` / `docs/交付总结-5.0.13`）

| 指标 | 优化前 | 优化后 | 说明 |
|---|---:|---:|---|
| 插件发现+加载（启动到可用） | 3177 ms（冷启动 8–11 s） | **555 ms** | 延迟导入重依赖 |
| DOCX 打开（含格式） | 17.7 s | **1.38 s** | 修复状态栏 O(N²) 全篇转换 |
| 5 万字 DOCX 端到端首次打开 | 5.85 s | **0.83 s** | 导入路径优化 |
| 蜜算滚动重绘 | 337 ms/帧（≈3 fps） | **23.6 ms/帧** | data()/flags() 热路径 |
| 大表加载 | 声明 20 万行样式全扫 119–154 s | 跳过 + 后台补全 | 不再分钟级阻塞 |

项目基线文档称：DOCX 打开与 WPS 的差距从 5.9–15.5 倍缩到 **1.2–1.5 倍**（该结论来自项目内测量，非本次同机盲测）。

### 2.2 结构性差距（定性）

| 维度 | WPS | BeeOffice | 影响 |
|---|---|---|---|
| 核心引擎 | C++ 原生 + 多年文档兼容积累 | Python + Qt + python-docx/openpyxl/pptx + 自研 XML | 超大文档/复杂版式/公式重算上限 |
| 渲染 | 自绘/硬件加速成熟 | QTextDocument/QTableView/QWebEngine 混合 | PPTX/PDF 预览、复杂对象渲染 |
| 冷启动 | 原生快速启动 + 预加载 | Python 导入 + 延迟插件（已优化） | 首屏仍可能慢于 WPS |
| 内存 | 原生对象模型 | pandas/QTextDocument 常驻 | 超大表/多文档内存压力 |
| AI | 云端大模型 + 端侧调度 | 本地/自带 Key，无云端额度 | 能力/速度/成本不同 |
| 云协作 | 全球节点 | WebDAV/局域网 | 协作体验差距 |

> **结论**：BeeOffice 的性能策略应是“**常见规模跟手、超大文件可降级/可取消、可后台**”，而不是追求 WPS 级全场景原生性能。应建立**同机同文件基准**（DOCX/XLSX/PPTX/PDF，冷/热缓存，P50/P95），避免单次测量误导。

## 3. GUI / UI 对比

### 3.1 WPS 的 UI 结构（公开可见）

- 顶部 **Ribbon 标签** + 左侧 **文件（Backstage）**；
- **上下文选项卡**（选中表格/图片/图表出现“表格工具/图片工具/图表工具”）；
- **任务窗格**（AI 助手、动画窗格、选择窗格、导航、批注、版本）；
- **模板启动中心**、最近文档、云文档；
- **命令搜索**（“告诉我”式入口）、快捷键提示；
- **皮肤/主题中心**、深浅色、强调色；
- 移动/桌面/网页一致的交互语言；
- WPS AI 侧栏与文档上下文联动（选中内容→AI 操作）。

### 3.2 BeeOffice 现状（v5.0.29）

已实现：
- Ribbon 标签（蜜写 7 页、蜜算 6 页、蜜演 5 页）；
- 分组框、组内多行、快速访问栏、大/小按钮、统一线性图标；
- **文件入口**：传统菜单栏视觉收起，文件菜单挂到 Ribbon 左上；
- **上下文标签**：蜜算选中单元格/蜜写光标进表格出现“表格工具”；
- 折叠功能区、浅色/深色主题、4 强调色、token 化；
- 统一菜单/状态栏/对话框基础风格。

仍缺（按影响排序）：

| 缺口 | 影响 | 优先级 |
|---|---|---|
| 真正 Backstage 文件页（新建/模板/最近/账户/打印一屏） | 启动与文件操作体验 | 高 |
| 任务窗格框架（AI/动画/选择/批注/导航） | 高级功能入口与屏幕利用率 | 高 |
| 图片/图表/文本框上下文选项卡 | 对象编辑效率 | 高 |
| 命令搜索/快捷键提示 | 学习成本 | 中 |
| 模板/素材启动中心 | 首次使用与内容生态 | 高 |
| 动画面板/母版/版式库 | 演示专业度 | 中 |
| 高 DPI/无障碍/触控模式 | 多设备体验 | 中 |
| 移动端编辑/投屏 | 多端 | 中 |

### 4.2 首批三个插件的具体形态

#### A. AI 文档助手
- 右侧任务窗格：选中文本→解释/改写/扩写/缩写/翻译/生成表格；
- 文档级 Q&A：对当前 DOCX/PDF/表格选区做 RAG（本地切片，不上传全文，除非用户授权）；
- 表格洞察：选区域→趋势/异常/公式建议；
- 演示：大纲→幻灯片、讲稿生成、图片建议；
- 能力复用现有 `beewrite_ai_mixin` / `beesheet_ai_mixin` / `beeshow_ai_service`，统一 Provider 抽象；
- 权限：`ai.network`、`doc.read`、`doc.write`；每次外发显示数据范围。

#### B. PDF 工具箱
- 文件列表/拖拽、页码范围、输出目录、预设（打印/归档/加密）；
- 复用 beecmd PDF 命令：merge/split/extract/delete/encrypt/watermark/text/images；
- 加“批注摘要/导出图片/PDF 信息”只读页；
- 不做 PDF↔Office 转换/OCR（可留第三方插件接口）。

#### C. 本地模板与素材中心
- 本地 `.bee-template` 包：封面、报告、简历、表格、PPT；
- 启动中心展示“最近/模板/示例”，支持分类/搜索/预览；
- 不运营云端内容，只提供包格式 + 校验 + 导入导出；
- 与现有 Ribbon“文件”入口打通。

## 5. 插件架构建议（从“整页插件”升级为“扩展点插件”）

### 5.1 现状问题

当前 `Plugin` 只有 `create_widget()`，一个插件基本等于一个编辑器 Tab；不能：
- 往现有蜜写/蜜算/蜜演 Ribbon 加按钮；
- 打开任务窗格；
- 监听文档事件/选区；

### 5.4 安全与工程约束

- **权限声明**：读文档、写文档、网络、本地文件、AI；安装时展示，运行时二次确认敏感操作；
- **API 版本**：`api_version` 主版本不兼容拒绝加载；
- **隔离**：首选同进程但禁用私有属性；高风险插件可子进程 + RPC；
- **可回滚**：插件写文档必须走 `ctx.doc.transaction()`，单步撤销；
- **可测试**：插件契约测试 + mock context；CI 加插件示例测试；
- **可分发**：`.beeplugin` zip + manifest + 签名/hash；现有插件市场做安装/禁用/更新；
- **可观测**：插件命令审计日志（谁、何时、改了哪个文档）。

## 7. 明确不做（结构性放弃）

- 云文档/网盘/多人实时协作/企业权限平台（需要服务端与网络效应）；
- 模板/素材/字体内容运营（内容成本高，只做本地包格式）；
- PDF 版面编辑、PDF↔Office 转换、OCR/翻译全家桶（重引擎/合规）；
- 在线表单/多维表格/企业 365；
- 追逐 WPS 的 AI 点数计费模式（BeeOffice 保持本地/自带 Key/可审计）。
