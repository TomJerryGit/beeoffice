## 2. P0：0–30 天（"能用"是前提）

| # | 事项 | 为什么现在做 | 估时 | 验收线 |
|---|---|---|---|---|
| **P0-1** | **`.pptx` 打开**（蜜演：只读 + 最小可编辑） | 审计与战略都标它是**门槛**：连别人的 PPT 都打不开，"流水线"故事不成立 | **3–5 人日** | 10 份真实 `.pptx` 打开不崩溃；文字/版式差异出报告（可接受损失明示） |
| **P0-2** | **蜜演真机验证矩阵**（R2） | 本机 QtWebEngine 起不来 → 播放/PPTX/PDF 导出全是 **C 级证据** | **1–2 人日** | 在能起 WebEngine 的机器上人工过一遍播放/放映/导出，结果写入 `docs/真机验证.md` |
| **P0-3** | **打包版"0 个插件"**（R11） | 5.0.10 冒烟实测：`插件目录不存在 + 已加载 0 个插件` —— 若影响核心模块则是发布阻断 | ~~1 人日~~ **✅ 已完成（第十六批）** | 打包版 `discover_plugins()` 与源码运行一致：冒烟日志 **`共加载 4 个插件`**（含 PDF 批注）✓ |
| **P0-4** | **`beecmd` v0.1**：`md ↔ docx`、`→pdf` | 依赖 Qt offscreen；复用既有导出/打印代码，直接扩大 CLI 覆盖面 | ~~2–3 人日~~ **✅ 已完成（第十七批）** | `md → docx` 写出**有内容**的 Word（4 段/42 字，词元级 verify 零差异 ✓）；`md → pdf` 产出 ≥1 页 ✓；**PDF 文本不可提取时 verify 返回退出码 3「不可判定」**（不假装通过/失败 ✓）；表格→PDF 明确拒绝 ✓ |
| **P0-5** | **崩溃恢复的"读取端"** | 审计发现"自动保存有写无读" —— 崩溃后拿不回 | **2 人日** | 强杀进程后重启能列出恢复候选并恢复；端到端测试 |
| **P0-6** | **i18n 44 个缺失键** | 非中文环境体验降级（成员/插件相关） | **0.5–1 人日** | 缺失键清零 + 门禁（键集合一致性测试） |

> **P0 完成判据**：上面 6 项的验收线全部打勾；`5.0.11` 发行包在**干净机器**安装并冒烟通过。

## 3. P1：30–90 天（"证明流水线"）

| # | 事项 | 为什么 | 估时 | 验收线 |
|---|---|---|---|---|
| **P1-1** | **保真报告对外**（50 份真实文档） | 竞品不敢做的透明化；也是 CLI 的第一个真实用途 | **3–5 人日** | 公开报告含：样本清单、损失率、失败样本；`beecmd verify` 可复现 |
| **P1-2** | **3 个自动化模板** | 让非程序员也能吃到 CLI | **5 人日** | ①合同批量转 PDF+校验 ②Excel 多表汇总 ③演示批量导出；每条**一条命令**跑通 |
| **P1-3** | **性能 UX 基线**（R8） | 现在只有"确定性门禁"，没有"手感"门禁 | **3–5 人日** | 打开 5 千/5 万行文件的耗时上限入 CI（超限失败）；大表滚动交互可用 |
| **P1-4** | **条件格式图标集/公式规则读回**（R6） | 目前只回读数据条/色阶，重度用户会丢设置 | **2 人日** | 图标集/公式规则往返测试 |
| **P1-5** | **一次真实交付（内部吃狗粮）** | 验证"流水线"不是纸上谈兵 | **2 人日** | 用 beecmd + 模板完成一份**真实工作交付**，全程不开 GUI，留 `audit.jsonl` |

> **P1 红线**：如果 P1-5 做不出来，**停止加功能**，回头检查是不是战略不成立。

| # | 事项 | 估时 | 验收线 |
|---|---|---|---|
| **P2-1** | **AI 任务化**（5 个任务：表格清洗、条款抽取、演示大纲、校对、摘要） | **10–15 人日** | 每个任务：输入契约 → 结构化输出 → **引用原文位置** → 可回滚；用本地 Ollama 实测 |

## 6. 依赖关系（先做哪个、为什么）

```
P0-3 打包插件数 ─┐
P0-1 pptx 打开 ──┼─→ P1-1 保真报告（要有能打开的文件才能报保真）
P0-4 CLI v0.1 ───┤
P0-5 崩溃恢复 ───┘
                     ↓
P1-2 模板 ─→ P1-5 真实交付 ─→ P2-1 AI 任务化 ─→ P2-2 DSL ─→ P3-1 SDK
                                   ↓
                              P2-3 内网部署 ─→ P2-4 扩展点 ─→ P3-2 垂直方案
```

**关键路径**：`P0-1（pptx）→ P1-1（保真报告）→ P1-5（真实交付）→ P2-1（AI 任务化）`。
这四步任何一步卡住，P3 的平台故事都不成立。

## 7. 明确不做（护栏，每季度复查）

| 不做 | 理由（详见战略文档 §6） |
|---|---|
| "WPS 免费替代品"定位 | 261 插件 vs 功能清单，结构上必输 |
| 云盘 / 云文档 / 协作 | 机房+带宽+合规；对方靠规模摊薄 |
| 模板 / 素材 / 字体市场 | 内容运营，不是工程 |
| AI 额度 / 点数计费 | 与"本地、透明"冲突；且 WPS 此路线正受争议 |
| 通用 PDF 全家桶（OCR/编辑/合并） | 已被免费方案覆盖；只保留"验收级"场景 |
| 移动 App / Web 版编辑 | 另一个产品；保留手机浏览器查看 |
| VBA 兼容层 | 投入产出比极差 |
| 功能数量军备竞赛 | 没有终点 |

## 8. 复盘点（每 30 天，只问四个问题）

1. **门槛项**（P0）有没有全部关闭？没关就**不进入 P1**。
2. **P1 红线**（无 GUI 完成真实工作）做到了吗？没做到就**不加功能**。
3. 新增的功能，有没有一个**可复现的验收**？（没有就不算完成）
4. 有没有在做 §7 里"不做"的事？（有就停下来）
