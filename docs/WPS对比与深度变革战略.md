# BeeOffice 深度变革战略：对比 WPS 与 WPS 会员

> 评估日期：2026-10-19 · 依据：本机 WPS 安装实测 + 仓库既有分析 + 公开资料
> 关联文档：`BeeOffice-功能真伪审计.md`（缺陷与修复）、`docs/生产能力评估.md`（能不能用）、
> `BeeOffice-与WPS差距分析及下一步工作.md`（差距分类与需求池）
> **本文回答的问题**：如果目标不是"免费替代品"，而是让 BeeOffice 真正有竞争力，
> **结构上必须改什么？**

---

## 0. 结论先行

| # | 判断 | 依据强度 |
|---|---|---|
| **1** | **不要再做"WPS 免费替代品"** —— 这条路线结构上必输。本机 WPS 是 **261 个插件**构成的平台，不是"几个功能"；它在编辑之外还有云、内容、计费、渠道四层护城河。 | **A（本机实测）** |
| **2** | **WPS 会员卖的是"云端资源与额度"**（AI 额度、云空间、模板素材、PDF 工具、去广告），本质是**内容 + 云 + 订阅**的生意。小团队**不可能也不该**在这种经济学上对标。 | **A/B**（功能面实测 + 公开资料） |
| **3** | BeeOffice 唯一的结构性机会：**换一个价值单位** —— 从"编辑一段文档的工具"变成"**可编程、可审计、本地优先的文档流水线**"。 | 推论（本文§4） |
| **4** | 这要求**架构级改造**（文档对象模型 API、headless CLI/SDK、批处理、本地 AI 任务化、可审计留痕），**不是再加 30 个功能**。 | 推论 |
| **5** | **"放弃清单"比"要做什么"更重要**。不放弃，就永远在别人的战场上用短板打长板。 | 推论 |

**一句话新定位**：
> BeeOffice = **本地优先的文档自动化与 AI 流水线**（编辑器只是它的前端）。

**两个结构性洞察（这是本文最重要的证据）**

1. **WPS 的 AI 是"云端 + 内嵌浏览器"形态**：37 个 AI 插件里大量是 `kweb*` 前缀 + `cef`（Chromium 内嵌浏览器）
   → AI 能力主要是**网页在云里跑**，本地只是个壳。这解释了为什么 WPS 的 AI 与**账号/会员额度**强绑定。
2. **会员变现是"内置在编辑器里"的**：`kappmarket`（应用市场）+ `kwebmemberrenewalpopup`（续费弹窗）+ `kspostpay`（支付）
   → 会员不是"产品外的一个选项"，而是**产品内部的一条收入流水线**。

### 1.4 这一节最重要的战略读数（三条，全部基于上面的事实）

**读数 1：AI 是 WPS 的"提价层"，不是免费层。**
超级会员不含 AI → 要 AI 得买大会员（+200 元/年）→ 重度使用还要买**灵点**（48–398 元），
且**31 天清零、大会员不抵扣**。这是**用户可感知的持续付费压力**，也是它口碑风险的来源（"套娃收费"）。

**读数 2：WPS 的增长引擎已经转向 B 端。**
WPS365 增速 **+60.8%**，个人订阅只有 **+15.2%** —— 说明它**不靠"更好的个人编辑器"赚钱了**，
靠企业协作与 AI 用量。所以**在 C 端做"免费更好用"是有空间的**（93% 免费用户是它不愿再投入的地方），
而**在 B 端正面撞 WPS365 是硬仗**（它已能私有化部署）。

**读数 3：BeeOffice 的差异点必须落在"AI 的计价方式"上，而不是"AI 的能力"上。**
我们**不需要在模型能力上超过它**（也超不过），只需要让"**它收费才有的东西**"
变成"**本来就不用加钱**"：本地模型（零边际成本）、不点数、不清零、可离线。
这是**商业模式层面的不对称**，不是功能层面的军备竞赛。

## 3. 为什么"功能对标"必输（结构性分析）

1. **成本结构不对称**：WPS 261 个插件 / 2.67 GB / 千人级团队；BeeOffice 134 文件 / 530 MB / 小团队。
   每补一个功能，对方的边际成本更低。
2. **经济结构不对称**：WPS 有"云+内容+订阅"三重收入；BeeOffice 若照抄，会陷入
   **"每多一个用户多一份云成本"** 的负循环（而 WPS 靠 6 亿级用户摊薄）。
3. **生态结构不对称**：模板、素材、字体是**内容运营**生意（需要采购/审核/版权），不是写代码能追的。
4. **渠道结构不对称**：预装、政企集采、移动端分发，BeeOffice 都没有。
5. **用户预期已被锚定**：用户会拿"会员价 100 多元/年 = 云空间+AI+模板+PDF"来要求你**免费给全部** ——
   这是一个**无法赢的比价**。

**结论**：正面对抗 = 用自己的短板打对方的长板。**要换战场，而不是加装备**。

## 4. 深度革命：把"价值单位"换掉

### 4.1 三个候选战略

| 选项 | 内容 | 优势 | 风险 |
|---|---|---|---|
| **A. 垂直纵深** | 只做一个行业的文档流水线（如律所合同、财务报表、教务材料） | 需求明确、可选价、WPS 不做定制 | 市场天花板低、销售重 |
| **B. 本地 AI 文档平台** | 离线可用 + 文档/表格/演示的 AI 任务化 + 可审计 | 与 WPS 的云 AI 形成结构性差异；契合已有资产（保真/本地 Ollama/插件化） | 需要架构改造；需说服"为什么不上 WPS 云" |
| **C. 文档引擎/嵌入** | 把"保真导入导出 + 渲染 + 打印"做成库/服务，供别的软件嵌入 | 避开消费级竞争；毛利高（B2B） | 需要稳定的 API/SDK；获客靠关系 |

**推荐：B 为核、C 为形、A 为切入** ——
用一个垂直场景（A）做付费验证，用 B 的差异化建立壁垒，用 C 的形态（SDK/CLI）扩大复用。

### 4.2 新定位与三个对外主张

> **BeeOffice = 文档的自动化流水线：本地跑、可审计、能编程。**

三条主张（每条都必须**可被验证**，否则就是营销话术）：
1. **"你的文件不离开你的机器"** —— 离线可用、无强制登录、AI 可本地推理（**已有实测**：Ollama 连通 ✓）。
2. **"每次转换都有一份保真报告"** —— 导入/导出给差异清单与位置（**已有基础**：损失报告 + 保真语料库）。
3. **"能被脚本调用"** —— 一条命令完成批量转换/生成/校验（**要新建**：这是革命的核心，见 §5）。

### 4.3 与 WPS 会员的正面差异（**不卖什么**）

| WPS 会员卖 | BeeOffice 不卖 | 换来什么 |
|---|---|---|
| AI 额度 | 不限额度（用你自己的模型/Key） | 无云成本、隐私可控 |
| 云空间 | 不卖空间（文件在你自己磁盘/NAS） | 无合规负担 |
| 模板素材 | 不卖内容（自带 + 你自己的） | 不背上内容运营 |
| PDF 全家桶 | 只做"**验收级**"单一场景（如合同批量转 PDF+校验） | 聚焦、可量化 |
| 去广告 | 本来就没广告 | 免费即可获得 |

## 5. 革命性变革的六个**架构级**改造（不是功能）

> 这六条是"能不能从编辑器变成流水线"的分水岭。缺任何一条，战略都落不了地。

### 5.1 文档对象模型（DOM）作为**对外 API**（已有内部基础）
现状：三模块各自持有自己的数据结构（QTextDocument / DataFrame / slides HTML）。
要改成：**统一的文档抽象**（段落/样式/表格/图片/批注/公式/幻灯片），
并提供 `open → inspect → transform → export` 的稳定接口。
> 这直接复用本轮做的**保真层**（`beesheet_style_export`、`_rich_to_docx`、`.beshow` 格式）。

### 5.2 Headless CLI + Python SDK（**当前完全缺失，这是最大缺口**）
现状：所有能力都绑在 GUI 上，无法被脚本/服务调用。

**✅ 2026-10-19 已落地 `beecmd` v0**（`beeoffice/beecmd.py`，纯 Python、**零 Qt**）：
```
python -m beeoffice.beecmd info    表.xlsx
python -m beeoffice.beecmd convert 表.xlsx --to csv -o 表.csv
python -m beeoffice.beecmd convert 表.csv --to xlsx -o 表.xlsx
python -m beeoffice.beecmd convert 讲稿.md --to beshow -o 讲稿.beshow
python -m beeoffice.beecmd verify  表.xlsx 表.csv --report 报告.json
python -m beeoffice.beecmd batch   jobs.json --audit audit.jsonl
```
已验证：xlsx↔csv/json/md/html **往返零差异**（逐格对比）；`verify` 精确报出
差异格子（如 `R1C3: 1.5 → 9.99`）并以**退出码 2** 区分；`batch` 失败不中断整批、
**失败也写审计流水**；表格路径**不 import PySide6**（子进程验证）；
BOM 容忍（真实踩过的坑）。测试 15 条 / 门禁 `beecmd`。

**v0.1 待接**（依赖 Qt offscreen）：`md ↔ docx`、`→ pdf`（复用既有打印引擎）。

### 5.3 本地 AI **任务化**（而非聊天框）
现状：AI 是"续写/润色/总结"几个按钮。
要改成：**可组合的任务**（表格清洗、合同条款抽取、演示大纲生成、校对），
每个任务：**输入契约 → 输出结构化结果 → 证据（引用原文位置）→ 可回滚**。
> 与 WPS 的"云端聊天 + 额度"形成鲜明差异；且复用已有的"AI 不得静默糊弄"纪律。

### 5.4 可审计流水线（把保真报告升级为"作业留痕"）
每一步（读了什么、改了什么、丢了什么、谁跑的）落成 `audit.jsonl`。
这是**企业/律所/财务愿意付费**的点 —— WPS 的个人会员不提供这个。

### 5.5 插件/扩展机制（内部先吃狗粮）
不是"应用市场"（那要运营），而是**稳定的扩展点**（自定义任务、自定义校验规则、自定义导出器）。
先用它把三模块的内部功能重写一遍（吃自己的狗粮），保证接口是真的。

### 5.6 可靠性与交付（把"能用"变成"敢用"）
已知缺口必须补：**崩溃恢复的读取端**、`.pptx` 打开、i18n 44 个缺键、
WebEngine 相关功能的真机验证、更新器、签名。
> 参考 `docs/生产能力评估.md` 的 §5 风险清单（R1/R2/R11 等）。

## 6. 必须放弃的（否则战略落空）

| 放弃 | 理由 |
|---|---|
| 做"WPS 免费替代品"的定位 | §3：结构上必输 |
| 云盘/云文档/协作 | 机房+带宽+合规；WPS 靠规模摊薄 |
| 模板/素材/字体市场 | 内容运营，不是工程 |
| AI 额度/点数计费 | 与"本地、透明"的新定位冲突；且 WPS 此路线正在引发争议 |
| 通用 PDF 全家桶（OCR/编辑/合并） | 单点工具已被免费方案覆盖；只保留"验收级"场景 |
| 移动 App / Web 版编辑 | 是另一个产品；保留手机浏览器查看即可 |
| VBA 兼容层 | 投入产出比极差（WPS 自己也最薄弱） |
| 追逐"功能数量" | 261 vs 134 的军备竞赛没有终点 |

## 7. 路线图（以"可验证"为单位）

> **详细排期见 [`docs/路线图.md`](路线图.md)**（P0/P1/P2/P3 分阶段，每项含估时、
> 验收线、依赖关系与"今天就能开始"的三件事）。下面是摘要。

### 90 天：把"流水线"证明一遍
- `beecmd` v0：`convert / verify / batch` 三个动词（复用现有导出与保真代码）
- **对外发布保真报告**（用现有语料库，跑 50 份真实文档，公开命中率与失败样本）
- 3 个自动化模板（可直接给人用的脚本）：合同批量转 PDF 并校验、Excel 多表汇总、演示批量导出
- **验收**：一个外部用户能在**无 GUI** 的情况下，用一条命令完成一件真实工作

### 6 个月：本地 AI 与可审计
- AI 任务化（≥5 个任务，每个带引用与回滚）
- 流水线 DSL（YAML）+ 并行 + `audit.jsonl`
- 企业内网部署包（离线安装、无外网依赖、可审计日志）
- **验收**：3 家内网/涉密场景用户完成试用；至少 1 家付费

### 12 个月：平台化
- Python SDK + 插件扩展点（第三方能写一个任务）
- 2 个垂直方案包（如律所合同 / 财务月报）
- 商业模式：**私有部署 + 定制流水线 + 支持**（不卖订阅）
- **验收**：收入 > 成本（至少覆盖 1 人）

## 8. 如何验证"这次不是自欺"（反自欺清单）

| 主张 | 可验证指标 | 现在的数 |
|---|---|---|
| 本地可用 | 断网后完成一次"打开→编辑→导出" | 未测（需真机断网验证） |
| 保真可验证 | 50 份真实文档的损失率 + 失败样本公开 | 语料库已有，**未跑 50 份真实文档** |
| 可编程 | CLI 与 GUI 产出逐字节/逐语义一致 | **CLI 尚不存在** |
| AI 不糊弄 | 每个 AI 结果可回落到"证据不可用" | 已有纪律，需扩展到任务化 |
| 有人愿意付费 | 至少 1 家内网用户付费 | 无 |

> **红线**：如果 90 天后仍拿不出"外部用户无 GUI 完成一件真实工作"的证据，
> 说明这条战略没有落地，应该**重新评估而不是继续加功能**。

## 9. 风险与应对

| 风险 | 程度 | 应对 |
|---|---|---|
| **PPTX 打不开**（蜜演） | 高 | 这是"能不能用"的门槛，必须先补；否则流水线故事不成立 |
| **WPS365 已能私有化部署 → "内网"不是真空** | 高 | 我们的差异不能停在"能私有化"，必须落在**轻量（530MB/免运维）+ 可编程（CLI/SDK）+ 无点数**；否则会被 WPS365 的合规资质与生态碾压 |
| **WPS 官方承诺"免费基础功能不降级"** | 中 | 说明"我更免费"本身不是壁垒；真正的壁垒是**能力形态不同**（流水线 vs 编辑器） |
| WebEngine 相关功能无法真机验证 | 高 | 建"真机验证矩阵"，作为发布门禁 |
| 小团队做平台 → 范围蔓延 | 高 | 用 §6 的放弃清单当护栏；每季度复查 |
| 免费竞品（LibreOffice/OnlyOffice） | 中 | 不与它们比"功能全"，比"可审计/可编程/本地 AI" |
| 无人付费 | 高 | 90 天内做付费验证（垂直场景 A） |
| 性能/大文件 | 中 | 已有门禁与惰性加载基础（R1 已做），CLI 场景更可控 |

## 10. 一页话术（给团队/投资人）

> WPS 用 **261 个插件**把"办公"做成了一个**云 + 内容 + 订阅**的平台，会员费买的是额度、空间和素材。
> 我们不可能、也不该在那条战线上赢。
> BeeOffice 的机会是把**文档变成可编程、可审计、可离线运行的流水线**：
> 同样的编辑能力，但**你的文件不离开你的机器、每次转换都有报告、每条命令都能被脚本调用**。
> 90 天的证明只有一个：**让别人在不开界面的情况下，用一条命令完成一件真实工作。**
