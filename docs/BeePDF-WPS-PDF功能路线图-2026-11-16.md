# BeePDF 参考 WPS PDF 功能优化路线图

日期：2026-11-16  
基线：BeeOffice v5.4.7 Beta  
范围：BeePDF（PDF 阅读/批注/页面工具）

## 1. 目标与原则

参考 WPS PDF 的页签和功能组织，不复制其品牌素材：

1. 页签对齐：开始 / 插入 / 编辑 / 页面 / 批注 / 工具 / 保护 / 转换 / AI；
2. 先补“读、批、页、转、护”五类高频能力；
3. 不承诺 pypdf 难以稳定实现的“任意 PDF 文字重排编辑”；
4. 所有写操作输出新文件，不破坏原文件；
5. OCR/Office 转换/AI 等外部能力必须可选、可降级。

## 5. 技术前置

1. **PDF 页面对象层**：页面缩略图、旋转、裁剪、排序统一模型；
2. **批注模型**：已存在，补撤销/重做、导入导出、烧录覆盖全部类型；
3. **安全模块**：加密、权限、证书签名、时间戳独立设计；
4. **转换适配层**：LibreOffice/OCR 作为可选插件，不写死依赖；
5. **渲染性能**：只渲染可视页，缩略图懒加载；
6. **测试**：每类操作输出新 PDF 后重新解析校验。

## 6. 建议执行顺序

```text
第 1 周：统一 Ribbon + 页面缩略图面板
第 2 周：页面管理 GUI + 批注增强/撤销
第 3 周：阅读体验 + 保护基础 + 转换基础
第 4 周：批注导入导出 + 回归测试 + Beta
第 5–8 周：插入工具/页面加工/文档对比
第 9 周起：保护增强/OCR/Office 转换/AI
```

## 7. 不承诺项

- 不承诺任意 PDF 文字/排版直接编辑（与 WPS 的复杂内容编辑差距最大）；
- 不复制 WPS 品牌图标/模板；
- 不在没有外部引擎时硬编码 Office/OCR 能力；
- 证书签名、电子签、密文等需独立合规评估。

## 8. 结论

BeePDF 的后端能力比 UI 更完整：合并/拆分/提取/加密/水印/书签/图片签名/批注烧录已有，但缺少 WPS PDF 那种统一页签和页面缩略图工作流。

优先补：

```text
统一 Ribbon → 页面缩略图/页面管理 → 批注增强 → 保护/转换基础
```

这比先做 AI/发票工具更符合日常 PDF 使用。
